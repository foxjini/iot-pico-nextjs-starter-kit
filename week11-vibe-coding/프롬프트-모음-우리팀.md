## 프롬프트 1 · 화면에 우리 팀 센서 추가

```
좋습니다. 그 순서대로 진행해 주세요.

먼저 화면부터 하겠습니다.
대시보드 page.tsx 에 [센서 이름] 을 추가해 주세요.

- key 는 "[        ]", label 은 "[        ]", unit 은 "[   ]", max 는 [    ] 입니다
- 지금 있는 센서들은 그대로 두세요

★ 센서 이름이 타입으로 못박혀 있습니다. 배열에 줄만 추가하면 타입 오류가 납니다.
  제 소스에서 아래에 해당하는 자리를 전부 찾아 같이 고쳐 주세요.
    - SensorKey 같은 유니온 타입에 이름 추가
    - SENSORS 배열에 항목 추가
    - SensorValue / SensorData 처럼 수신 데이터 타입이 있으면 거기도
    - sensorValues 처럼 값을 모으는 객체가 있으면 거기도
    - getSensorStatus 처럼 정상/주의/위험을 판정하는 함수가 있으면 거기도
  제 소스에 없는 것은 만들지 마세요.

- 파일 전체 완성본으로 주세요
- 바뀐 줄에 // ★ 주석을 달아 주세요
```

**확인**: 붙여넣고 새로고침 → **카드가 생기는가** / **빨간 줄(타입 오류)이 없는가**
값은 아직 `데이터 없음` 이 **정상입니다.** Pico 가 아직 그 키를 안 보내니까요.

> 🚨 **「카드가 생기는가」를 건너뛰지 마세요.** 타입 오류는 빨간 줄로 바로 보이지만,
> **`SENSORS` 배열을 빼먹은 것은 아무 오류도 안 납니다.** 타입 세 곳만 고쳐도 컴파일은
> 멀쩡히 되는데 **화면에 카드만 안 생깁니다.** 화면은 `SENSORS.map()` 으로 그리기 때문입니다.
> 이걸 모르고 넘어가면 다음 시간에 *"Pico 가 값을 안 보내나?"* 하면서 배선부터 다시 뜯어봅니다.
> **오류가 없는 것과 되는 것은 다릅니다.**

### 타입 오류가 떴을 때 — 메시지로 어디를 빼먹었는지 알 수 있습니다

| 오류 메시지 | 빠뜨린 곳 |
|---|---|
| `Type '"키"' is not assignable to type 'SensorKey'` | `type SensorKey` 유니온 |
| `Property '키' does not exist on type 'SensorValue'` | `type SensorValue` |
| `Property '키' is missing … required in type 'Record<SensorKey, …>'` | `sensorValues` 모으는 객체 |
| **오류는 없는데 카드가 안 보인다** | **`SENSORS` 배열** |

메시지를 그대로 복사해서 **프롬프트 5** 로 물어보면 됩니다.

> ⚠️ **액추에이터**를 추가할 때는 `SwitchState` 타입 · `SWITCHES` 배열 · `INITIAL_SWITCHES`
> 세 곳입니다. 그리고 **RGB LED 가 아닌 장치**(펌프·릴레이)는 그냥 넣으면
> **RGB 버튼 칸에 끼어 들어갑니다.** 항목에 `group` 을 하나 더 붙여 달라고 하세요 —
> 규칙 문서 §3-7 에 그대로 적혀 있습니다.

## 프롬프트 4 · 자동 재연결 — **전시 필수**

여기가 오늘의 본 과제입니다. **전시장에서 Wi-Fi 는 반드시 한 번은 끊깁니다.**
지금 여러분 화면은 끊기면 **사람이 「다시 연결」을 눌러야** 합니다.
전시 중에 아무도 안 누르면 **작품이 고장 난 것처럼 보입니다.**

```
전시회에서 몇 시간 동안 무인으로 켜 둘 예정입니다.
Wi-Fi 가 한 번 끊기면 지금은 사람이 「다시 연결」을 눌러야 합니다.

연결이 끊기면 자동으로 다시 연결을 시도하게 해 주세요.

- 3초마다 다시 시도해 주세요
- "연결 끊기" 를 눌러서 끊은 경우에는 다시 연결하지 마세요
- 다시 시도하는 중임을 화면에 보여 주세요 (지금 있는 "연결 중" 표시를 그대로 쓰세요)

★ 타이머 안에서는 useState 값이 "소켓을 열던 시점의 옛날 값" 으로 보입니다.
  타이머가 읽어야 하는 것(연결을 원하는 상태인지, IP 주소, 지금 연결 상태)은
  useRef 로 두고 읽어 주세요.

★ 재연결 중에 센서 값을 지우지 마세요.
  지금은 다시 연결할 때 값을 null 로 비우는데, 그러면 전시 중에 화면이 깜빡입니다.
  마지막 값을 흐리게(opacity 를 낮춰) 남겨 두고, 다시 연결되면 선명하게 돌려 주세요.

★ 자동으로 다시 붙는 중에는 "다시 연결" 안내 카드를 띄우지 마세요.
  사람이 직접 끊어 둔 경우에만 띄웁니다.

- 페이지를 벗어날 때 타이머가 남지 않게 정리해 주세요

대시보드 page.tsx 전체 완성본으로 주세요.
```

**확인 — 오늘 가장 중요한 확인입니다.** 가상 Pico 창에 **`x`** 를 치세요.

| 무엇을 한다 | 어떻게 되어야 한다 |
|---|---|
| 연결한다 | **ONLINE** |
| 가상 Pico 창에 **`x`** (USB 뽑기) | **「재연결 중…」** 으로 바뀌고, **값이 흐리게 남아 있다** |
| **아무것도 안 누르고 5초 기다린다** | **저절로 ONLINE** 으로 돌아온다 |
| 「연결 끊기」 를 누른다 | **OFFLINE 그대로** (다시 안 붙는다) |

> 🚨 **네 번째 줄을 빠뜨리기 쉽습니다.** 사람이 일부러 끊었는데 3초 뒤에 다시 붙으면
> **연결을 끊을 방법이 없어집니다.**

# 붙여넣기 전 검수

## 공통
- [ ] 코드의 **마지막 줄이 `}` 로 제대로 끝나는가** (중간에 잘리지 않았는가)
- [ ] 첫 줄이 **`"use client";`** 인가
- [ ] `npm install` 을 하라는 말이 없는가

## 화면 코드
- [ ] **Bootstrap 클래스가 없는가** — `d-flex`, `g-3`, `fs-5`, `text-body-secondary`, `row`, `col-md-6`
- [ ] `react-bootstrap` 을 import 하지 않았는가
- [ ] **`const UI` 객체를 그대로 쓰는가** (`globals.css` 에 `@theme` 을 만들지 않았는가)
- [ ] **연결 상태 구분(`"offline"` / `"online"` …)과 Error · Empty 화면이 그대로** 있는가
- [ ] 센서를 늘렸다면 **타입까지 같이** 고쳤는가 (빨간 줄이 없는가)

## Pico 코드 (`main.py`)
- [ ] **`machine`, `utime`, `network`** 가 없는가 → 있으면 MicroPython
- [ ] `import board`, `digitalio`, `analogio`, `pwmio` 를 쓰는가
- [ ] `pin.value = True` 형태인가 (`pin.value(1)` 이면 MicroPython)
- [ ] 읽기 실패 시 **`None`** 을 돌려주는가

## 센서를 새로 붙이는 경우라면
- [ ] AI 가 알려준 **전원이 3V3(오른쪽 레일)인가 외부 5V(왼쪽 레일)인가** 확인했다
- [ ] **Pico 로 들어오는 신호가 5V 가 아닌가** — 5V 면 **분압 저항을 먼저** 달았다
- [ ] 핀이 **GP23·24·25·29 가 아닌가** (무선 칩 전용)
- [ ] 아날로그라면 **GP27 또는 GP28** 인가
- [ ] **`code.py` 로 그 센서만 시험해서 숫자를 봤다** → 보고 나서 **지웠다**

## 붙여넣은 뒤
- [ ] **딱 한 가지만 확인** — 이번에 요청한 것이 되는가
- [ ] 고치기 전 파일을 **`.bak`** 으로 복사해 뒀는가
