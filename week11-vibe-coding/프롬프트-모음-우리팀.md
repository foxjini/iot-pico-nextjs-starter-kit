# 11주차 프롬프트 모음 — 우리 팀 작품으로

> 전시회까지 수업은 **이번 시간과 14주차 두 번**입니다.
> 오늘은 **우리 팀 센서·액추에이터를 붙이고**, **전시장에서 끊겨도 저절로 돌아오게** 만듭니다.

## 🚨 먼저 — 오늘은 **대화를 네 번 나눠서** 합니다

한 대화에서 끝까지 가지 **않습니다.** 단계마다 **새 대화를 열고 지금 소스를 다시 올립니다.**

| | 대화 | 받는 것 |
|---|---|---|
| **대화 1** | 프롬프트 0 · 계획 | 코드 없음 — 어디를 고칠지 목록만 |
| **대화 2** | **화면** — 센서 + 액추에이터를 **한 번에** | `page.tsx` 전체 완성본 **1회** |
| **대화 3** | **Pico** — 센서 + 액추에이터를 **한 번에** | `main.py` 전체 완성본 **1회** |
| **대화 4** | 자동 재연결 | `page.tsx` 전체 완성본 **1회** |

> 🐞 **왜 이렇게 바꿨나 — 2026-10-23 3학년 모의 수업에서 실제로 겪은 일입니다.**
> 전에는 한 대화에서 프롬프트 0 → 1 → 2 → 1-B → 2-B → 4 를 쭉 갔습니다.
> 그러면 한 대화 안에 `page.tsx` 가 **세 벌**, `main.py` 가 **두 벌** 쌓입니다.
> 학생이 쓰는 **제미나이 무료 모델은 대화가 길어지면 무너집니다** —
> 뒤로 갈수록 **오류가 나는 코드**를 내놨습니다.
> **대화를 끊고 지금 저장된 파일을 다시 올리면** AI 가 늘 진짜 현재 상태를 봅니다.

> ⚠️ **대화를 새로 열 때마다 `node bundle-source.js` 를 다시 돌리세요.**
> 방금 붙여넣은 코드가 들어간 **새 `우리팀-소스.md`** 를 올려야 합니다.
> 예전 것을 다시 올리면 AI 가 **되돌려 놓습니다.**

> **오류가 없는 것과 되는 것은 다릅니다.**

### 타입 오류가 떴을 때 — 메시지로 어디를 빼먹었는지 알 수 있습니다

| 오류 메시지 | 빠뜨린 곳 |
|---|---|
| `Type '"키"' is not assignable to type 'SensorKey'` | `type SensorKey` 유니온 |
| `Property '키' does not exist on type 'SensorValue'` | `type SensorValue` |
| `Property '키' is missing … required in type 'Record<SensorKey, …>'` | `sensorValues` 모으는 객체 |
| **오류는 없는데 카드가 안 보인다** | **`SENSORS` 배열** |

- [ ] 액추에이터를 넣었다면 **그 키를 받아 핀을 움직이는 코드가 있는가**

- [ ] 액추에이터를 **시작할 때 꺼진 상태로 초기화**했는가 (안 하면 전원을 넣자마자 움직입니다)
