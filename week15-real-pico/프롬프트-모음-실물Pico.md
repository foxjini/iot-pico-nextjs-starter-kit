# 15주차 프롬프트 모음 — 가상 Pico 를 진짜 Pico 로

> **오늘 하는 일은 한 문장입니다.**
> 여러분 화면은 **가상 Pico 가 보내던 JSON** 에 맞춰 만들어졌습니다.
> **진짜 Pico 가 똑같은 JSON 을 보내게** 하면, 화면은 **한 글자도 안 고쳐도 됩니다.**

| 구간 | 시간 | 하는 일 |
|---|---|---|
| 준비 | 20분 | 실물 Pico 켜기 · 라이브러리 세 개 확인 · 올릴 파일 세 개 |
| 프롬프트 0 | 20분 | **무엇이 다른지 표로 받기** — 아직 코드를 고치지 마세요 |
| 프롬프트 1 | 25분 | **빠진 공통 키 채우기** (`cpu_temp` · `discomfort`) |
| 프롬프트 2 | 30분 | **우리 팀 센서를 진짜로 읽기** |
| 프롬프트 3 | 20분 | **우리 팀 액추에이터 움직이기** |

## 시작 전에 — 이것부터 확인하세요

### ① 라이브러리 세 개가 `CIRCUITPY/lib` 에 있는가

| 넣을 것 | 모양 | 빠뜨리면 |
|---|---|---|
| `adafruit_httpserver` | **폴더** (`.mpy` 파일 하나가 아닙니다) | `ImportError: no module named 'adafruit_httpserver'` |
| `asyncio` | **폴더** | `import asyncio` 가 안 됩니다 — **CircuitPython 에 내장이 아닙니다** |
| `adafruit_ticks.mpy` | 파일 | `ImportError: no module named 'adafruit_ticks'` ← **가장 많이 빠뜨립니다** |

`circup install asyncio` 를 쓰면 `adafruit_ticks` 까지 같이 깔립니다.

### ② `settings.toml` 에 Wi-Fi 정보가 들어 있는가

```toml
CIRCUITPY_WIFI_SSID = "실습실 공유기 이름"
CIRCUITPY_WIFI_PASSWORD = "비밀번호"
```

> 🚨 **이 파일은 절대 AI 에게 올리지 마세요.** 실습실 공유기 비밀번호가 들어 있습니다.
> 코드에서는 `os.getenv("CIRCUITPY_WIFI_SSID")` 로 읽습니다 — **비밀번호를 코드에 직접 쓰지 마세요.**

### ③ `code.py` 를 지웠는가

CircuitPython 은 **`code.py` 가 있으면 `main.py` 를 아예 실행하지 않습니다.**
센서 하나를 시험하려고 만들었다면 **지우거나 `code.py.bak` 으로** 이름을 바꾸세요.
**코드가 다 맞는데 연결조차 안 되는 1순위 원인입니다.**

### ④ 올릴 파일 **세 개**

| 올리는 것 | 왜 |
|---|---|
| `mock-pico/mock_pi_11.py` | **무엇을 보내야 하는지의 정답지** |
| 내 `main.py` | 지금 진짜 Pico 코드 (3주차 것 + 11주차에 고친 것) |
| `프로젝트-규칙.md` | CircuitPython 규칙 — **§11 이 오늘 핵심입니다** |

❌ `settings.toml` 은 **올리지 않습니다.**

## 프롬프트 0 · 무엇이 다른지 표로 받기

```text
첨부한 파일 세 개를 먼저 읽어 주세요.
- 프로젝트-규칙.md : 지켜야 할 규칙입니다. §11 을 특히 잘 읽어 주세요.
- mock_pi_11.py   : 윈도우 PC 에서 진짜 Pico 를 흉내 내던 프로그램입니다.
- main.py         : 진짜 Pico 에서 도는 지금 코드입니다.

제 화면(대시보드)은 mock_pi_11.py 가 보내던 JSON 에 맞춰 만들어져 있습니다.
이제 진짜 Pico 가 그와 똑같은 JSON 을 보내게 하려고 합니다.

★ mock_pi_11.py 에서 가져올 것은 "무엇을 보내는가" 하나뿐입니다.
  그 파일은 PC 용 파이썬(CPython)이라 socket · threading 으로 WebSocket 을 직접 만들었지만,
  진짜 Pico 는 CircuitPython 이고 adafruit_httpserver + asyncio 를 씁니다.
  제 main.py 의 통신 구조(server.route · Websocket · async 태스크 세 개 · run(main()))는
  그대로 두세요.

──────────────────────────────
아직 코드를 고치지 마세요.
먼저 아래 네 가지만 답해 주세요.

1. mock_pi_11.py 의 build_payload() 가 보내는 JSON 키를 전부 적어 주세요.
2. 그중에서 제 main.py 가 아직 안 보내고 있는 키는 무엇인지
3. 그 키를 진짜 Pico 에서는 무엇으로 만들 수 있는지 (부품이 필요한지, 계산인지)
4. 어떤 순서로 고치면 좋을지
```

> 🎯 **2번의 답이 오늘 할 일 목록입니다.** 3주차 `main.py` 는 `temperature` · `humidity` ·
> `light_percent` **세 개만** 보냅니다. 가상 Pico 는 **다섯 개 + 팀 센서**를 보냅니다.
> **`cpu_temp` 와 `discomfort` 가 빠져 있는 것**을 AI 가 찾아내면 제대로 읽은 것입니다.

> ⚠️ **AI 가 「socket 으로 서버를 만들겠다」거나 「threading 을 쓰자」고 하면 멈추세요.**
> 가상 Pico 의 구조를 베끼려는 것입니다. **프롬프트 5(규칙 위반)** 로 되돌리세요.

```text
좋습니다. 먼저 빠진 공통 키부터 채우겠습니다.

main.py 의 send_sensor_messages() 가 보내는 payload 에
cpu_temp 와 discomfort 를 추가해 주세요.

- cpu_temp : 칩에 들어 있는 온도계를 쓰세요. 부품을 새로 붙이지 않습니다.
- discomfort : mock_pi_11.py 의 _discomfort() 와 같은 식을 쓰세요.
  온도나 습도가 None 이면 계산하지 말고 None 을 넣어 주세요.

- 지금 보내고 있는 temperature · humidity · light_percent 는 그대로 두세요
- 읽기에 실패하면 None 을 돌려주세요. 0 으로 때우지 마세요
- 통신 구조(server.route · Websocket · async 태스크)는 건드리지 마세요
```

**확인**: 시리얼 모니터의 `[WS] 송신 메시지` 에 **`cpu_temp` 와 `discomfort` 가 들어 있는가**
→ 화면의 그 두 카드에 **값이 들어오는가** (전에는 「데이터 없음」이었을 것입니다)

> 💡 **`cpu_temp` 는 부품이 없어도 읽힙니다.** `microcontroller.cpu.temperature` 는 칩 안에
> 들어 있는 온도계라, 배선을 하나도 안 해도 값이 나옵니다. **가장 먼저 성공하는 센서**입니다.

## 프롬프트 2 · 우리 팀 센서를 진짜로 읽기

> 🚨 **코드보다 전압이 먼저입니다.** Pico 의 핀은 **3.3V 까지**입니다. 센서가 Pico 로
> **내보내는 신호**가 5V 면 그 핀이 망가집니다 (HC-SR04 의 ECHO 가 대표적 — 분압 필수).
> **배선은 USB 를 뽑은 상태에서** 하고, **GND 를 반드시** 이으세요.

```text
이제 우리 팀 센서를 진짜로 읽게 해 주세요.

- 센서 이름: [        ]
- JSON 키: "[        ]"   (가상 Pico 에서 add 로 쓰던 그 이름과 같아야 합니다)
- 핀: [        ]
- 연결 방식: [아날로그 / 디지털 / I2C / UART]
- 값의 범위: [        ]

가상 Pico 는 이 값을 지어내고 있었습니다. 진짜 핀에서 읽어서
같은 범위의 숫자가 나오도록 바꿔 주세요.

- raw 값을 위 범위로 바꾸고, 범위 밖으로 나가면 가둬 주세요
- 읽기에 실패하면 None 을 돌려주세요
- 지금 보내고 있는 다섯 개 키는 그대로 두세요

main.py 전체 완성본으로 주세요.
```

**확인**: 센서를 **손으로 건드리면** 시리얼의 값이 **따라 움직이는가**
→ 화면 카드의 숫자도 같이 움직이는가

> 💡 **값이 이상하면 센서 하나만 따로 시험하세요.** `code.py` 로 그 센서만 읽어 `print` 해
> 보면, 의심할 곳이 **다섯 군데에서 두 군데로** 줄어듭니다. (끝나면 `code.py` 를 꼭 지우세요)

| 시리얼에 나온 것 | 뜻 |
|---|---|
| 숫자가 변한다 | ✅ 성공 |
| 계속 **0** 이다 | 전원(3V3) 또는 신호선이 안 닿았다 |
| 계속 **65535** 다 | **GND 가 안 이어졌다** |
| `No pulldown` 같은 오류 | 그 핀은 아날로그가 아닙니다 — **GP27 또는 GP28** 로 |

## 프롬프트 3 · 우리 팀 액추에이터 움직이기

```text
이제 화면에서 보낸 명령으로 우리 팀 액추에이터를 움직이게 해 주세요.

- 액추에이터 이름: [        ]
- JSON 키: "[        ]"
- 핀: [        ]
- 켜짐은 255, 꺼짐은 0 으로 받습니다 (지금 RGB LED 와 같은 방식)

- handle_websocket_requests() 안에서 적용해 주세요
- command.get("키", 0) 으로 받아서, 그 키가 안 와도 나머지가 동작하게 해 주세요
- 시작할 때 꺼진 상태로 초기화해 주세요.
  안 그러면 전원을 넣자마자 움직입니다
- 지금 있는 RGB LED 와 서보 처리는 그대로 두세요

main.py 전체 완성본으로 주세요.
```

**확인**: 화면에서 버튼을 누르면 → 시리얼에 `[WS] 수신 메시지` 와 `[WS] 명령 적용 완료`
→ **실물이 움직이는가**

> 🚨 **모터·펌프를 3V3 에서 먹이지 마세요.** `3V3(36번 핀)` 은 다 합쳐 **약 300mA** 입니다.
> 넘으면 **Pico 가 꺼졌다 켜집니다** — 대시보드가 자꾸 끊기는 1순위 원인입니다.
> **외부 5V(브레드보드 왼쪽 빨강 레일)** 에서 받으세요. **Pico 의 VBUS 는 쓰지 않습니다.**

> ⚠️ **스텝모터를 쓰는 팀은 한 번에 다 돌리면 안 됩니다.** `time.sleep()` 으로 1024스텝을
> 한 번에 돌리면 **그 몇 초 동안 WebSocket 이 멈춰 대시보드가 끊어집니다.**
> *"루프가 한 번 돌 때마다 몇 스텝씩만 움직이게 해 주세요"* 를 넣으세요.

## 프롬프트 4 · 센서 하나가 죽어도 안 멈추게

```text
전시회에서 몇 시간 동안 켜 둘 예정입니다.
센서 하나가 읽기에 실패해도 Pico 가 멈추지 않게 해 주세요.

- 센서를 읽는 곳마다 try / except 로 감싸고, 실패하면 None 을 돌려주세요
- 한 센서가 실패해도 나머지 센서값은 그대로 보내야 합니다
- DHT11 은 가끔 읽기에 실패합니다. 실패하면 직전 값을 그대로 쓰고,
  2초보다 자주 읽지 마세요 (센서 규격입니다)
- 실패했을 때 시리얼에 무엇이 실패했는지 한 줄 찍어 주세요

main.py 전체 완성본으로 주세요.
```

**확인**: 센서 하나의 **신호선을 뽑아도** → 그 값만 「데이터 없음」이 되고
**나머지는 계속 들어오는가** / 시리얼에 **Traceback 이 안 뜨는가**

> 🎯 **이것이 전시회에서 제일 중요합니다.** 센서 하나가 빠졌다고 `main.py` 가 멈추면
> **화면 전체가 죽습니다.** 관람객에게는 「작품이 고장 났다」로 보입니다.

## 마무리 · 가상 Pico 를 끄고 진짜 Pico 로만

**가상 Pico 창을 완전히 닫으세요.** 이제 진짜 Pico 만 남습니다.

- [ ] Pico 시리얼 모니터에서 **IP 를 확인**하고 화면에 넣었다
- [ ] 화면이 **ONLINE** 이 된다
- [ ] 센서 카드에 **「데이터 없음」이 하나도 없다** ← 키를 빠뜨리면 여기서 걸립니다
- [ ] 센서를 손으로 건드리면 **값이 따라 움직인다**
- [ ] 화면에서 버튼을 누르면 **실물이 움직인다**
- [ ] **USB 를 뽑았다가 다시 꽂으면** 화면이 저절로 ONLINE 으로 돌아온다 (11주차 프롬프트 4)
- [ ] **30분 동안** 시리얼에 Traceback 이 한 번도 안 뜬다

> 🚨 **마지막 줄이 전시 가능 여부를 가릅니다.** 30분을 못 버티면 6시간은 못 버팁니다.

### 진짜 Pico 에서만 생기는 것들 — 미리 알아 두세요

| 일어나는 일 | 왜 | 어떻게 |
|---|---|---|
| **IP 가 매번 바뀐다** | 공유기가 그때그때 나눠 줍니다 | **켤 때마다 시리얼에서 확인**해서 화면에 넣으세요 |
| 전엔 되던 Wi-Fi 가 안 붙는다 | 새로 쓴 핀이 **GP23·24·25·29** | 무선 칩 전용 핀입니다 |
| 몇 초 뒤 끊긴다 | `main()` 안에서 예외가 나서 멈춘 것 | 시리얼의 **Traceback** 을 보세요 |
| 값이 1초마다 안 온다 | 어딘가에서 **`time.sleep()`** 으로 멈춰 있음 | `await async_sleep()` 으로 |
| Pico 가 자꾸 재부팅된다 | 모터·펌프를 **3V3** 에서 먹임 | **외부 5V** 로 옮기세요 |

## 붙여넣기 전 검수

- [ ] `machine` · `utime` · `network` 가 **없는가** → 있으면 MicroPython (잘못된 것)
- [ ] **`socket` · `threading` 이 없는가** → 있으면 **가상 Pico 코드를 베낀 것**
- [ ] `import board`, `analogio`, `digitalio`, `pwmio` 를 쓰는가
- [ ] `pin.value = True` 형태인가 (`pin.value(1)` 이면 MicroPython)
- [ ] **`time.sleep()` 이 없는가** → `await async_sleep()` 이어야 합니다
- [ ] `server.route` · `Websocket` · `run(main())` **구조가 그대로**인가
- [ ] 보내는 JSON 에 **다섯 개 공통 키 + 우리 팀 센서**가 전부 있는가
- [ ] 읽기 실패 시 **`None`** 인가 (`0` 이 아니라)
- [ ] **비밀번호를 코드에 직접 쓰지 않았는가** (`os.getenv` 로 읽어야 합니다)
