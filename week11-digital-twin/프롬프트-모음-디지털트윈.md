# 11주차 프롬프트 모음 — 우리 작품을 **3D 방으로** 옮깁니다

> 🎯 오늘은 **2D 화면을 한 글자도 안 고칩니다.**
> 새 주소 `/twin` 에 **같은 데이터를 3D 로** 보여 주고, 고치는 파일은 **하나**입니다.

---

## 🚨 먼저 — 오늘은 화면을 다시 디자인하지 않습니다

| 오늘 **안 하는** 것 | 왜 |
|---|---|
| 2D 대시보드 고치기 | **9주차에 무인 리허설로 통과시킨 화면**입니다. 건드리면 그 통과가 사라집니다 |
| 3D 코드 직접 쓰기 | `page.tsx` 는 선생님이 검증해서 드립니다. **열지 마세요** |
| 색·글꼴 다시 고르기 | 7주차 심화 19단계에서 끝냈습니다 |

| 오늘 **하는** 것 |
|---|
| 우리 팀 장치를 **방 어디에 놓을지** 정하기 |
| **위험한 장치**를 가려내기 |

## 🚨 제미나이는 **실행할 수 없습니다**

제미나이는 우리 컴퓨터에서 `npm run dev` 를 돌릴 수도, 브라우저를 열어 볼 수도 없습니다.
**「확인했습니다」라고 말해도 그것은 확인이 아닙니다.**

AI 에게 받는 것은 **「확인 결과」가 아니라 「확인할 목록」**이고, 실제로 눌러 보고
적는 사람은 **여러분**입니다.

## 시작 전에 — 선생님이 준 파일을 자리에 놓습니다 (10분)

```
선생님이 준 파일                    →  우리 프로젝트의 어디에
─────────────────────────────────────────────────────────────
page_twin_reference.tsx            →  src/app/twin/page.tsx
team_twin_example.ts               →  src/app/twin/team-twin.ts     ← 여기만 고칩니다
page_office_fallback.tsx           →  src/app/office/page.tsx
```

> 💡 **세 파일인데 설정 파일은 하나입니다.** `/twin` 과 `/office` 가 **같은
> `team-twin.ts` 를 같이 읽습니다.** 그래서 한 곳만 고치면 두 화면이 같이 바뀌고,
> 3D 가 깨져 폴백으로 넘어가도 **우리 팀 작품**이 그대로 뜹니다.

그리고 라이브러리 세 개를 받습니다. **버전을 바꾸지 마세요.**

```bash
npm install three@0.182.0 @react-three/fiber@9.8.2 @react-three/drei@10.7.9
npm run dev
```

브라우저에서 **`http://localhost:3000/twin`** 을 엽니다.

### ✅ 여기서 멈추고 확인하세요

- [ ] `/twin` 에 **방이 보인다** (아직 장치 이름은 남의 팀 것이어도 됩니다)
- [ ] `/dashboard` 가 **예전 그대로** 뜬다 ← **이게 제일 중요합니다**
- [ ] `src/app/dashboard/page.tsx` 를 **한 글자도 안 고쳤다**

> ⚠️ 방이 안 보이고 **「이 컴퓨터에서는 3D 를 켤 수 없습니다」** 가 뜨면,
> 그 컴퓨터는 WebGL 이 꺼져 있는 것입니다. **고장이 아닙니다.**
> 버튼을 눌러 `/office` 로 가면 3D 없이 같은 내용을 볼 수 있습니다.
> **전시는 그 화면으로 해도 됩니다.**

## 11-1 · 자리 배치도 — **손으로 먼저 그립니다** (15분)

> 💻 **이 단계에는 컴퓨터를 쓰지 않습니다.** 워크시트에 연필로 적습니다.

방에는 자리가 **여섯 곳**입니다.

| 자리 이름 | 어디 | 어울리는 것 |
|---|---|---|
| `shelf` | 창가 선반 | 조도 · 온도처럼 바깥과 관계있는 센서 |
| `desk` | 책상 위 | 아무 센서나 |
| `wall` | 벽 | 표시등 · 경고등 |
| `ground` | 바닥 한가운데 | 흙 · 물처럼 바닥에 있는 것 |
| `corner` | 구석 | 펌프 · 팬처럼 큰 장치 |
| `ceiling` | 천장 | 조명 |

### 워크시트에 적을 것

1. 우리 팀 장치를 **전부** 적습니다. 옆에 **Pico JSON 키**를 그대로 적습니다.
2. 각 장치를 **어느 자리**에 놓을지 고릅니다. **같은 자리에 둘을 놓지 마세요.**
3. **주인공 하나**에 동그라미 — 전시 모드에서 가장 크게 나옵니다.
4. **위험한 장치**에 ⚠️ — 아래 기준으로 가릅니다.

### ⚠️ 위험한 장치를 가르는 기준 (9주차 J3 과 같습니다)

| 물음 | 예 → **위험** |
|---|---|
| **물**이 나오는가 | 펌프 · 밸브 · 분무기 |
| **열**이 나는가 | 히터 · 열선 |
| **움직이는가** | 서보 · 모터 · 문 |
| 눌렀다 다시 누르면 **되돌아오는가** | 아니오 → **위험** |

> 💡 LED · 부저는 **위험이 아닙니다.** 전부 위험으로 적으면 전시 모드에서
> **관람객이 만질 것이 하나도 안 남습니다.**

### 📋 프롬프트 1 — 우리 팀 테마 파일 (전체 완성본 **1회**)

```
올려드린 team-twin.ts 는 3D 디지털 트윈 화면이 읽는 설정 파일입니다.
이 파일의 TWIN 객체만 우리 팀 작품에 맞게 바꿔 주세요.

우리 팀 정보
- 팀 이름: (여기에 적으세요)
- 작품 주제: (예: 스마트 화분)
- 방 종류: farm | home | factory | park 중 하나

우리 팀 장치 (11-1 워크시트에 적은 그대로 옮기세요)
| JSON 키 | 센서/액추에이터 | 이름 | 자리 | 단위 | 주의 | 위험 | 주인공 | 위험장치 |
|---|---|---|---|---|---|---|---|---|
| soil | 센서 | 토양수분 | ground | % | 30 | 15 | O | |
| pump | 액추에이터 | 물 펌프 | corner | | | | | O |
| (우리 팀 것으로 다 채우세요)

지켜 주세요
- **TWIN 객체 안의 내용만** 바꾸세요. 위쪽 타입 정의(type)는 한 글자도 건드리지 마세요.
- key 는 Pico 가 주고받는 JSON 키 **그대로**입니다. 한글로 바꾸지 마세요.
- hero 는 **하나만** 적습니다.
- spot 은 서로 **겹치지 않게** 합니다.
- 올려드린 프로젝트-규칙.md 의 §13 을 지켜 주세요.
- **team-twin.ts 전체 완성본을 한 번만** 주세요. 설명은 코드 뒤에 짧게 붙여 주세요.
```

### ✅ 받은 뒤 — **우리가 아는 것으로 검산합니다**

- [ ] `type` 으로 시작하는 윗부분이 **그대로**인가 (바뀌었으면 되돌리세요)
- [ ] `key` 가 전부 **영어**이고, 2D 화면의 `SENSORS` key 와 **글자 하나까지** 같은가
- [ ] `hero: true` 가 **딱 하나**인가
- [ ] `spot` 이 서로 **다른가**
- [ ] 위험한 장치에만 `risk: "high"` 가 붙었는가

붙여넣고 브라우저를 새로고침합니다.

- [ ] 방 안에 **우리 팀 장치 이름**이 전부 보인다
- [ ] 왼쪽 목록에도 **같은 개수**가 보인다
- [ ] 겹쳐서 안 보이는 장치가 **없다**

> 🐞 **장치 하나가 안 보이면** `spot` 이 겹친 것입니다. 워크시트를 다시 보세요.
> 이름이 **「데이터 없음」**에서 안 바뀌면 `key` 가 틀린 것입니다.

## 11-3 · 승인 게이트 — 위험한 장치는 **먼저 묻습니다** (15분)

코드는 이미 들어 있습니다. 오늘은 **그게 진짜로 막는지 확인**합니다.

### 확인 방법 — 가상 Pico 창을 **보면서** 누릅니다

| 순서 | 누르는 것 | 가상 Pico 창에 |
|---|---|---|
| 1 | 안전한 장치(LED) **켜기** | `[WS] 수신 메시지` 가 **1줄** 찍힌다 |
| 2 | 위험한 장치(펌프) **켜기** | ❗ **아무것도 안 찍힌다** · 화면에 말풍선만 뜬다 |
| 3 | 말풍선의 **[승인]** | 그때서야 `[WS] 수신 메시지` 가 **1줄** |

### ✅ 확인

- [ ] 2번에서 가상 Pico 창에 **새 줄이 하나도 안 생겼다** ← 이게 핵심입니다
- [ ] [나중에] 를 누르면 말풍선만 닫히고 **아무것도 안 보낸다**
- [ ] 승인한 뒤에 `-> 우리 팀 액추에이터 pump: 255 (켜짐)` 이 찍힌다

> 💡 **왜 이렇게 합니까?** 전시장에서 관람객이 호기심으로 펌프를 켜고 그냥 갑니다.
> 물이 계속 나옵니다. **묻는 한 번**이 그것을 막습니다.

## 11-4 · 「이 명령이 실제로 간 길」 — **오늘의 핵심** (15분)

오른쪽 **기록** 탭을 엽니다. 방금 보낸 명령이 네 줄로 나뉘어 있습니다.

| 줄 | 뜻 |
|---|---|
| ① 화면이 보냈다 | 우리 브라우저가 send() 를 끝냈다 |
| ② 연결은 살아 있다 | 보낸 뒤 2초 안에 센서값이 또 왔다 |
| ③ Pico 가 받아서 적용했다 | Pico 가 **적용값을 되돌려 보냈고** 그 값이 보낸 값과 같다 |
| ④ **실물이 실제로 움직였다** | ❌ **이 화면은 끝까지 알 수 없습니다** |

### 🚨 ④ 가 왜 영원히 안 체크됩니까

③ 이 체크되었다는 말은 **「Pico 안의 변수가 바뀌었다」**는 뜻입니다.

- 펌프 선이 **빠져 있어도** ③ 은 체크됩니다.
- 펌프가 **타 버렸어도** ③ 은 체크됩니다.

**④ 를 확인하는 방법은 하나뿐입니다 — 눈과 귀.**
실물이면 장치가 움직이는지 보고, 가상 Pico 면 창에
`-> 우리 팀 액추에이터 … (켜짐)` 줄이 찍히는지 봅니다.
펌프에 짝이 되는 센서(토양수분)가 있다면 **그 값이 움직이는 것**이 간접 증거입니다.

> 🚨 **④ 가 체크되게 코드를 고치면 그건 거짓말입니다.** 선생님 쪽 시험에 걸립니다.

### ③ 이 「아직 응답 없음」이면

우리 팀 Pico 가 **적용값을 아직 안 보내는 것**입니다. **고장이 아닙니다.**
10주차 자료로 `main.py` 에 `applied` 를 더하면 체크되기 시작합니다. 시간이 없으면
**그대로 두고 전시해도 됩니다.**

### ✅ 확인

- [ ] 안전한 장치를 켜면 ① ② 가 **금방** 체크된다
- [ ] (Pico 를 고친 팀) ③ 도 체크된다
- [ ] **④ 는 어떤 경우에도 체크되지 않는다**
- [ ] 가상 Pico 창에서 **`e`** 를 누르면 ③ 이 **「아직 응답 없음」**으로 바뀐다
      (다시 `e` 를 누르면 돌아옵니다)

## 11-5 · 전시 모드와 **되돌아갈 길 두 겹** (20분)

### 전시 모드

머리줄의 **[전시 모드]** 를 누릅니다.

- [ ] IP 입력칸과 버튼들이 **사라진다**
- [ ] **위험한 장치가 아예 안 보인다** ← 관람객이 못 켭니다
- [ ] 안전한 장치는 **남아 있다** ← 해 볼 거리가 있어야 합니다
- [ ] **주인공 값이 크게** 나온다 (1m 밖에서 읽히는지 실제로 떨어져서 보세요)
- [ ] 화면이 **저절로 안 꺼진다** (몇 분 두고 보세요)
- [ ] **ESC** 를 누르면 조작 화면으로 돌아온다

### 되돌아갈 길 — 전시 당일에 쓸 수도 있습니다

```
/twin  ──[3D 없는 화면]──▶  /office  ──[2D 로 돌아가기]──▶  /dashboard
```

- [ ] `/twin` 에서 **[3D 없는 화면]** 을 누르면 `/office` 가 뜬다
- [ ] `/office` 에서 **[2D 로 돌아가기]** 를 누르면 `/dashboard` 가 뜬다
- [ ] `/dashboard` 가 **9주차 그대로**다 (아무것도 안 바뀌었어야 합니다)

> 💡 **전시 당일 아침에 3D 가 이상하면 주소만 바꾸면 됩니다.** 1초면 됩니다.
> 그러려고 2D 를 안 건드린 것입니다.

- [ ] 화면이 **안 꺼졌다**

> ⚠️ **하나라도 못 지키면 2D 로 전시합니다.** 아쉬워하지 마세요 —
