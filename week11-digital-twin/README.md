# 11주차 · UI 를 디지털 트윈으로 (2차 완성)

노션 교재 **「11주차 · 디지털 트윈 — 우리 작품을 3D 방으로」** 의 배포 파일입니다.

학생들은 18세 미만이라 AI 에이전트형 도구에 제약이 있어, **학교 구글 계정의 제미나이 채팅**에
파일을 올리고 프롬프트로 요청하는 **컨텍스트 엔지니어링** 방식을 씁니다.
8 · 9 · 10주차와 같은 방법이고, **고치는 파일이 딱 하나**라는 점만 다릅니다.

## 🚩 언제 하는가 — 차시가 아닙니다

이번 운영의 수업은 **1 · 2 · 3 · 4 · 5 · 6 · 7 · 8 · 9주차** 이고,
10 · 11주차는 그 뒤에 붙이는 차시가 아니라 **작품 제작 시간에 쓰는 자료**입니다.

| 단계 | 무엇 |
|---|---|
| 9주차까지 | **1차 완성** — 2D 화면이 전시장에서 버티는 상태 |
| 10주차 자료 | 가상 Pico → 실물 Pico |
| **11주차 자료** | **2차 완성** — UI 를 디지털 트윈으로 |

> 🚨 **순서를 지켜 주세요.** 1차 완성(9주차 무인 리허설 통과)을 **먼저** 끝낸 팀만 11주차로
> 갑니다. 2D 가 아직 흔들리는데 3D 를 얹으면 **둘 다 못 쓰게 됩니다.**
>
> 🚨 **3D 로 전시하려면 무인 리허설 30분을 3D 로 다시 통과해야 합니다.**
> 9주차에 2D 로 통과한 것은 2D 에 대한 통과입니다. 통과 못 하면 2D 로 전시합니다 —
> **그것도 완성입니다.**

## 오늘 하는 일은 한 문장입니다

> 2D 화면은 **한 글자도 건드리지 않고**, 새 주소 `/twin` 에 **같은 데이터를 3D 방으로** 보여 줍니다.
> 학생이 고치는 것은 **우리 팀 정보를 적는 파일 하나**뿐입니다.

### 화면이 세 개가 됩니다 — 전시장에서 되돌아갈 길이 두 겹

```
/twin        3D 디지털 트윈   ← 전시 기본
  └ 3D 가 안 뜨면 ─→ /office     CSS 만으로 그리는 화면 (WebGL 불필요)
       └ 그것도 이상하면 ─→ /dashboard   9주차까지 만든 2D (검증 끝난 화면)
```

`/twin` 은 페이지를 열 때 **WebGL 을 먼저 시험**합니다. 안 되면 3D 를 아예 띄우지 않고
「이 컴퓨터에서는 3D 를 켤 수 없습니다 — **작품이 고장 난 것이 아닙니다**」 안내와 함께
`/office` 로 가는 버튼을 보여 줍니다.

## 오늘의 교육 포인트 — **3D 는 더 잘 속입니다**

버튼을 누르면 3D 모형이 움직입니다. 그래서 학생도 관람객도 **「됐다」고 느낍니다.**
그런데 **그림이 바뀐 것과 펌프가 돈 것은 다릅니다.**

`/twin` 의 「이 명령이 실제로 간 길」 패널은 그것을 네 줄로 갈라 놓았습니다.

| 줄 | 체크되는 조건 | 화면이 아는가 |
|---|---|---|
| ① 화면이 보냈다 | `readyState === OPEN` 이고 `send()` 가 예외 없이 끝남 | **압니다** |
| ② 연결은 살아 있다 | 보낸 뒤 2초 안에 센서 메시지가 또 옴 | **압니다** |
| ③ Pico 가 받아서 적용했다 | `applied` 가 같은 값으로 돌아옴 | **이제 압니다** |
| ④ **실물이 실제로 움직였다** | — | ❌ **끝까지 모릅니다** |

**④ 가 이 주차의 핵심입니다.** ③ 은 *Pico 안의 변수가 바뀌었다*는 뜻입니다.
**선이 빠져 있어도 ③ 은 체크됩니다.** 펌프가 타 버렸어도 체크됩니다.
④ 를 확인하는 방법은 하나뿐입니다 — **눈과 귀.**

> 9주차의 *"「미검증」을 「통과」로 적지 마세요"* 가 여기서 한 칸 더 들어갑니다.
> **④ 가 체크되게 코드를 고치면 그것은 거짓말입니다.** 회귀 테스트로 막아 두었습니다.

## ★ 명령 응답 — 10주차 Pico 코드를 조금 고칩니다

지금까지의 통신 규약에는 **명령에 대한 답장이 없었습니다.** 그래서 ③ 을 알 수 없었습니다.
1초마다 보내는 센서 JSON 에 `applied` 를 **하나 더 싣습니다.**

```python
# main.py — 명령을 적용한 자리에서 기억해 두고
applied["pump"] = 255 if pump.value else 0

# 1초마다 보내는 payload 에 같이 싣습니다
payload = json.dumps({ ..., "applied": applied })
```

**키를 더하기만 하므로 2D 대시보드는 모르는 키라 무시하고 그대로 돕니다.** (하위호환)

| 우리 팀 Pico 는 | 트윈의 ③행 |
|---|---|
| `applied` 를 보낸다 | 값이 맞으면 **체크됨**, 다르면 **「응답은 왔는데 값이 다릅니다」** |
| 아직 안 고쳤다 | **「아직 응답 없음 — 고장이 아닙니다」** |

> 💡 **안 고쳐도 트윈은 돕니다.** 옵트인입니다. 시간이 없으면 ③ 을 비워 둔 채 전시해도 됩니다.
> 가상 Pico 창에서 **`e`** 를 누르면 「안 고친 Pico」를 흉내 내므로, 두 경우를 다 보여 줄 수 있습니다.

## 학생이 고치는 단 하나의 파일

`src/app/twin/team-twin.ts` — **데이터만 적습니다. 코드가 없습니다.**

```ts
export const TWIN: TwinConfig = {
  teamName: "3팀 · 스마트 화분",
  room: "farm",                     // farm | home | factory | park
  devices: [
    { key: "soil", kind: "sensor", label: "토양수분", spot: "ground",
      unit: "%", max: 100, warn: 30, danger: 15, hero: true },
    { key: "pump", kind: "actuator", label: "물 펌프", spot: "corner", risk: "high" },
  ],
};
```

| 적는 것 | 뜻 |
|---|---|
| `key` | **Pico JSON 키 그대로.** 틀리면 그 장치는 영원히 「데이터 없음」 |
| `room` | 방 네 종류. 바닥·벽 색과 가구가 바뀝니다 |
| `spot` | 자리 여섯 곳 (`shelf` `desk` `wall` `ground` `corner` `ceiling`). **좌표를 안 씁니다** |
| `hero` | 주인공 하나. 전시 모드에서 **36px 로 크게** 나옵니다 |
| `risk: "high"` | **승인 게이트 + 전시 모드에서 숨김**을 한꺼번에 켭니다 (9주차 J3 기준) |

## 검증 결과 (2026-10-24)

가상 Pico(`../mock-pico/mock_pi_08.py`)를 띄우고 Chromium 으로 **55건 통과 / 0 실패**.

| 무리 | 확인한 것 |
|---|---|
| 첫 화면 | OFFLINE · 팀 이름 · 방 이름 · 장치 5개 · `sensor===null` 이면 「연결 대기」 |
| 연결 | ONLINE 전환 · 값이 오면 「정상」 · 3D 라벨 5개가 **전부** 뜸 |
| 없음 3종 | `fail soil` → 그 센서만 「데이터 없음」, 나머지 멀쩡 · 되살리면 복귀 |
| 안전 장치 | 바로 전송(수신 1건) · 가상 Pico 가 `LED:(255` 적용 |
| **위험 장치** | **승인 전 수신 0건** · 말풍선 · 승인 뒤 1건 · `pump: 255 (켜짐)` |
| **네 줄 패널** | ①②③ 체크 · **④ 는 「알 수 없습니다」이고 체크 표시가 없음** |
| **응답 없는 Pico** | `e` 로 끈 뒤 ③ 이 **「아직 응답 없음 · 고장이 아닙니다」** |
| 자동 재연결 | `x` → 「재연결 중」 + 흐리게(opacity 0.6) → 저절로 ONLINE |
| 전시 모드 | IP 칸 숨김 · **위험 장치 숨김** · 안전 장치 남음 · **주인공 36px** · 끄면 복귀 |
| 되돌아갈 길 | `/dashboard` 정상 · `/office` 정상 |
| **WebGL 끔** | `--disable-gpu` → 안내 문구 → 폴백 이동 → 폴백 렌더까지 |

### 🐞 만들면서 찾은 함정 — **장치 하나가 조용히 사라집니다**

`@react-three/drei` 의 `<Html>` 은 **첫 번째 인스턴스만 글자가 비어서** 나옵니다
(React 19 / Next 16 실측). 장치 배열 **맨 앞 하나**가 껍데기만 생기고 사라지는데,
**오류가 한 줄도 안 납니다.** 순서를 바꾸면 사라지는 것도 따라 바뀝니다.

→ **포털 그릇을 우리가 만들어 모든 `<Html>` 에 넘겨서** 비켜 갔습니다
(`page_twin_reference.tsx` 의 `labelRef`). 그 줄을 지우면 다시 사라집니다.
