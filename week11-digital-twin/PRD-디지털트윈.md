# PRD v2.0 — 팀별 주제를 담는 3D 디지털 트윈 대시보드

> 📌 이 문서는 선생님이 쓰신 **`3D_IoT_Dashboard_Platform_PRD.md` 의 개정본**입니다.
> 원본은 **플랫폼 한 벌을 Phase 0~5 에 걸쳐 새로 짓는** 문서였습니다. 이 저장소의 실제
> 조건(1학년 · 제미나이 플래시 채팅 · 학교 노트북 · 11월 20일 전시 · 남은 시수)에 맞춰
> **범위를 줄이고 제약을 더했습니다.**
>
> 원본이 Phase 0 에서 하라고 한 **「기존 시스템 조사」는 끝냈고, 그 결과가 §2 기준선**입니다.
> 조사하면서 **원본의 전제 몇 가지가 실제와 달랐다는 것**을 확인했으므로 §3 에 적어 둡니다.

## 1. 무엇을 만드는가

> 2D 대시보드를 **한 글자도 건드리지 않고**, 새 주소 `/twin` 에 **같은 데이터를 3D 방으로**
> 보여 준다. 팀마다 다른 작품을 담되, **학생이 고치는 것은 설정 파일 하나**다.

### 1.1 왜 하는가

- **관람객이 숫자를 못 읽습니다.** 「토양수분 23%」보다 **마른 화분이 깜빡이는 방**이 빠릅니다.
- **학생이 자기 작품을 공간으로 설명할 수 있게** 됩니다 — 어느 장치가 어디에 붙었는지.
- **3D 는 더 잘 속입니다.** 버튼을 누르면 그림이 바뀌니까 「됐다」고 느낍니다.
  그 착각을 **교육 소재로 뒤집는 것**이 이 주차의 핵심입니다 (§5).

### 1.2 비목표 (원본 §1.4 를 그대로 잇되 더 좁혔습니다)

- VR / AR · 물리 시뮬레이션 · 외부 3D 모델 파일
- 2D 대시보드의 개편 · 통신 규약의 **교체**
- 여러 팀 작품을 한 화면에 모으는 관제 화면
- **추가** — 카메라 연출(궤도 애니메이션 · 시네마틱), 캐릭터 대사, 채팅 입력창

## 4. 요구사항

### FR-01 · 3D 방 렌더링
- `three` + `@react-three/fiber` 9.8.2 + `@react-three/drei` 10.7.9 **딱 세 개**.
- 외부 모델 파일 **0개.** 바닥 · 벽 · 선반 · 책상 · 화단을 **기본 도형**으로.
- 카메라는 고정 시작 + **제한된 궤도**(각도·거리를 묶음, 이동 없음).

### FR-02 · 팀별 테마 — **학생이 고치는 단 하나의 파일**
- `team-twin.ts` 의 `TWIN` 객체만. **코드가 아니라 데이터.**
- 방 **4종** × 자리 **6곳**. 원본의 *스타일 5 × 공간 6 × 카메라 3 × 캐릭터 5* 는
  조합이 너무 많아 1학년이 길을 잃습니다 (원본 §9.2 가 스스로 경계한 바).
- 좌표는 학생이 쓰지 않습니다.

### FR-03 · 장치 표시
- 센서는 구, 액추에이터는 상자. 상태를 **색 + 아이콘 + 글자** 셋 다로.
- 값 글자는 **3D 텍스처가 아니라 진짜 DOM 글자**로 띄웁니다 —
  1m 밖 가독성과 화면 읽기 프로그램 때문입니다.

### FR-04 · 「없음」 세 가지 구분 (9주차에서 이어짐)
- 아직 한 번도 못 받음(`sensor === null`) → **연결 대기**
- 그 센서만 없음(`value === null`) → **데이터 없음**
- 재연결 중이라 마지막 값 유지(`stale`) → **흐리게**

### FR-05 · 위험한 장치 승인 게이트
- `risk: "high"` 하나가 **승인 말풍선 + 전시 모드에서 숨김**을 한꺼번에 켭니다.
- **승인 전에는 WebSocket 에 아무것도 보내지 않습니다.** (실측으로 고정)

### FR-06 · 2D 와의 관계
- `/dashboard` 는 **수정 0줄.** `/twin` → `/office` → `/dashboard` 로
  **한 번씩** 내려갈 수 있어야 합니다.

### FR-07 · WebGL 이 없을 때
- 페이지를 열 때 WebGL 을 **먼저 시험**하고, 안 되면 3D 를 띄우지 않고
  「고장이 아닙니다」 안내와 함께 `/office` 로 보냅니다.
- *(원본에 없던 요구입니다. 전시장 노트북에서 실제로 일어납니다.)*

### FR-08 · 전시 모드
- 9주차 것을 **그대로** 씁니다 — WakeLock · 전체화면 · `visibilitychange` ·
  `fullscreenchange`. 더하는 것은 **주인공 값 크게**와 **위험 장치 숨김**뿐.

### FR-09 · 시뮬레이션
- **새로 만들지 않습니다.** 가상 Pico(`mock_pi_08.py`)가 이미 그 일을 합니다.
  `e` 명령으로 **「적용값을 안 보내는 Pico」**까지 흉내 낼 수 있게 더했습니다.

### FR-10 · 접근성
- 모든 3D 라벨은 **버튼**이고 `aria-label` 에 「이름 — 상태 — 값」이 들어갑니다.
- 색만으로 알리지 않습니다. 초점 표시(`focus-visible`)를 유지합니다.

## 5. ★ target ↔ reported — 이 주차가 가르치는 것

원본 **§3.2** 는 *"3D 캐릭터 애니메이션만으로 명령 성공을 표현해서는 안 된다"* 고 했습니다.
그 원칙을 **화면 한 칸으로 승격**시켰습니다.

### 5.1 통신 규약을 **더합니다** (바꾸지 않습니다)

Pico 가 1초마다 보내는 센서 JSON 에 `applied` 를 **하나 더** 싣습니다.

```json
{ "temperature": 23.1, "humidity": 47, "light_percent": 48.4,
  "cpu_temp": 40.0, "discomfort": 69.2, "soil": 62,
  "applied": { "led_r": 255, "led_g": 0, "led_b": 0, "servo_angle": 90, "pump": 255 } }
```

- **키를 더하기만 하므로** 2D 대시보드는 모르는 키라 무시하고 그대로 돕니다 (하위호환).
- **옵트인**입니다. 안 고친 팀도 트윈이 그대로 돌아갑니다.
- 실측 확인 — 명령 전 `applied` 가 전부 0, `{led_r:255, pump:255}` 를 보낸 뒤
  같은 값으로 돌아왔습니다.

### 5.2 네 줄로 갈라 적습니다

| 줄 | 체크 조건 | 화면이 아는가 |
|---|---|---|
| ① 화면이 보냈다 | `readyState === OPEN` 이고 `send()` 가 예외 없이 끝남 | **압니다** |
| ② 연결은 살아 있다 | 보낸 뒤 2초 안에 센서 메시지가 또 옴 | **압니다** |
| ③ Pico 가 받아서 적용했다 | `applied` 가 같은 값으로 돌아옴 | **이제 압니다** |
| ④ **실물이 실제로 움직였다** | — | ❌ **끝까지 모릅니다** |

③ 은 네 가지로 갈립니다.

| 상태 | 화면에 |
|---|---|
| 값이 맞게 돌아옴 | **체크됨** |
| 보낸 지 4초가 안 지남 | 「— 아직」 |
| `applied` 는 왔는데 값이 다름 | **「응답은 왔는데 값이 다릅니다」** — Pico 가 키를 다르게 읽고 있음 |
| `applied` 가 아예 안 옴 | **「아직 응답 없음 · 고장이 아닙니다」** |

### 5.3 ④ 는 **설계상 체크될 수 없습니다**

③ 은 *Pico 안의 변수가 바뀌었다*는 뜻입니다. **선이 빠져 있어도 ③ 은 체크됩니다.**
④ 를 확인하는 길은 **눈과 귀**뿐입니다.

> 9주차의 *"「미검증」을 「통과」로 적지 마세요"* 가 여기서 한 칸 더 들어갑니다.
> ④ 가 어떤 상태로도 체크되지 않는다는 것을 **회귀 테스트로 고정**했습니다.

## 8. 제미나이(무료 플래시 모델) 제약 — 신설

8 · 9주차 운영에서 얻은 교훈을 그대로 적용합니다.

- **전체 완성본 요구는 수업 중 1회.** 긴 대화에서 플래시 모델이 무너집니다.
- **올리는 파일은 두 개** — `team-twin.ts` 와 `프로젝트-규칙.md`.
  `page.tsx`(1,100줄 이상)는 **올리지 않습니다.**
- 프롬프트 첫 문장이 **계획 전체를 실행하라는 허가로 읽히지 않게** 씁니다.
- AI 에게 받는 것은 **「확인 결과」가 아니라 「확인할 목록」**입니다 —
  제미나이는 빌드도 브라우저도 돌릴 수 없는데 「확인했습니다」라고 말합니다.
