# 10주차 · 가상 Pico 를 진짜 Pico 로

노션 교재 **「10주차 · 가상 Pico 를 진짜 Pico 로」** 의 배포 파일입니다.

학생들은 18세 미만이라 AI 에이전트형 도구에 제약이 있어, **학교 구글 계정의 제미나이 채팅**에
소스와 규칙 문서를 올리고 프롬프트로 요청하는 **컨텍스트 엔지니어링** 방식을 씁니다.
8 · 9주차와 같은 방법이고, **대상만 Pico 코드로** 바뀝니다.

---

## 🚩 언제 하는가 — 팀마다 다릅니다

이번 운영의 수업은 **1 · 2 · 3 · 4 · 5 · 8 · 9주차** 일곱 번이고, 10주차는 그 뒤에
붙이는 차시가 아니라 **작품 제작 시간에 쓰는 자료**입니다. 다만 **순서가 중요합니다.**

| 우리 팀은 | 언제 |
|---|---|
| **가상 Pico 로만 개발해 왔다** (실물로 한 번도 안 돌려 봄) | 🚨 **9주차 무인 리허설 전에 반드시** |
| 실물 Pico 로 이미 센서가 다 들어온다 | 9주차 뒤에 해도 됩니다 (팀 센서 추가분만) |

> **9주차 무인 리허설의 두 번째 항목이 「가상 Pico 창에 `x`」 입니다.**
> 전시장에는 가상 Pico 가 없습니다. **실물로 옮기지 않으면 리허설을 통과해도 전시가 안 됩니다.**

## 0단계 · 실물 하드웨어 단독 점검 (백엔드와 붙이기 전에)

**`../worksheets/수정 배선도.pdf`** 대로 조립했으면, **화면·서버 없이 Pico 혼자서** 센서와 액추에이터가
도는지부터 봅니다. 여기서 안 되는 것은 화면을 아무리 고쳐도 안 됩니다.

1. **`code_hardware_selftest.py`** 를 `CIRCUITPY` 루트에 **`code.py`** 로 저장
   (`main.py` 보다 먼저 실행됩니다. Wi-Fi 를 안 쓰므로 `settings.toml` 은 필요 없습니다)
   `lib/` 의 `adafruit_dht.mpy` · `adafruit_motor/` 는 **펌웨어와 같은 주 버전(10.x) 번들**에서 꺼내야 합니다 —
   다르면 `Incompatible .mpy file` 오류가 납니다.
2. **`pico_monitor/run_monitor.bat`** 을 더블클릭해 시리얼 모니터를 엽니다 (아래 「시리얼 모니터 앱」)
3. 아래가 맞는지 봅니다 (한 바퀴 약 15초, 계속 반복합니다. 멈출 필요 없이 끝나면 `code.py` 이름만 바꾸면 됩니다)

| 항목 | 정상 | 기준 (코드 맨 위 상수) |
|---|---|---|
| **내장 LED** | **1초에 한 번 깜빡임** = 코드가 돌고 있음. 꺼지거나 켜진 채 멈추면 → 시리얼 모니터의 오류 확인 | — |
| 온도 | `[OK]` | 24 ℃ ±4 (`TEMP_REF`, `TEMP_TOL`) |
| 습도 | `[OK]` | 50 % ±15 (`HUMI_REF`, `HUMI_TOL`) |
| 조도 | `[OK]` · **손으로 가리면 값이 내려감** | LED 조명 실내 85 %, 70 % 아래면 경고 (`LIGHT_REF`) |
| 서보 | **90° → 180° → 90° → 0° → 90°** 순서로 천천히 | — |
| LED | 각도에 **도착하면** 0° 빨강 · 90° 초록 · 180° 파랑 | — |

- 조도 85 % 는 CdS + 10 kΩ 분압으로 계산한 **대략값**입니다. 함께 찍히는 `raw` 값을 보고 우리 교실 값으로 고쳐 적으세요.
- `[실패]` 줄은 **어디를 보라**고 알려 줍니다 — DHT11 무응답(GP16·3V3·GND), CdS 빠짐(raw ≈ 65535),
  10 kΩ 빠짐·자리 바뀜·**레일 끊김**(raw ≈ 0).
- 0° 나 180° 에서 서보가 **웅웅거리며 떨면** 끝에 걸린 것입니다(제품마다 끝 위치가 조금 다름). 회로 문제가 아닙니다.
- 서보가 떨거나 Pico 가 리셋되면 **외부 5V 어댑터**와 **왼쪽↔오른쪽 파랑 공통 GND** 를 확인하세요.
- 서보는 **평균 45°/초, 출발·도착은 부드럽게(가속·감속)** 돕니다. 빨리 돌면 순간 전류로 5V 가 떨어져
  서보가 멈추거나 이상하게 움직이기 때문입니다. 그래도 그러면 코드 맨 위 `SERVO_SPEED` 를 30 으로 낮추고,
  **커패시터(470~1000µF)** 가 서보 전원 레일에 꽂혀 있는지 보세요.
  처음 켤 때 한 번은 90° 로 바로 움직입니다(서보가 어디 있는지 알 수 없어서) — 이때 리셋되면 전원 문제입니다.
- 🚨 **점검이 끝나면 `code.py` 를 지우거나 `code.py.bak` 으로** — 안 지우면 `main.py` 가 실행되지 않습니다.

### 🖥️ 시리얼 모니터 앱 — `pico_monitor/` (VS Code 없이)

학생 노트북(Windows 11)에 **파이썬만 있으면** 됩니다. `pico_monitor` 폴더를 통째로 복사해 주고
**`run_monitor.bat` 더블클릭** (또는 `py pico_monitor.py`).

| 파일 | 역할 |
|---|---|
| `pico_monitor.py` | 앱 본체 (tkinter — 파이썬 기본 포함) |
| `pyserial-3.5-py2.py3-none-any.whl` | 시리얼 통신 라이브러리. **설치하지 않아도** 앱이 이 파일을 직접 불러옵니다 (`pip` 이 막힌 PC 대비) |
| `run_monitor.bat` | 더블클릭 실행 (`py` 가 없으면 `python` 으로) |
| `PYSERIAL_LICENSE.txt` | pyserial 라이선스 (BSD) |

화면 (밝은 테마 · 위에서 아래로)
- **한 줄 판정** — 지금 가장 중요한 것 하나와 **할 일**. 예) `✖ 문제 2개 — 온도 · 습도` → `DHT11 응답 없음 — DATA=GP16 · VCC=3V3 · GND · 레일 가운데 끊김 확인`.
  모두 괜찮으면 초록 `✔ 모두 정상`
- **점검표 8칸** — 연결 · 코드 · 라이브러리 · 온도 · 습도 · 조도 · 서보 · LED 를 초록(정상) · 호박(주의) · 빨강(실패) · 회색(아직 모름)으로
- **센서 칸** — 값 · 상태 · 최근 값 추세선(조도는 손으로 가리면 선이 내려감) · `raw`
- **서보 · LED** — 각도 게이지와 **90→180→90→0→90 순서 점**(이번 회차에 어디까지 왔는지), LED 색
- **시리얼 출력** — 원래 출력 그대로(색 구분). `멈춤` · `다시 시작` · **`라이브러리 검사`**(REPL 에서 직접 import 해 보고
  보드 · 펌웨어 · 내장 모듈까지 확인한 뒤 점검 코드를 다시 실행) · **`점검 줄만`**(센서 · 서보 · 오류 줄만 보기) · `지우기` · `저장`
- **맨 아래 상태줄** — 보드 · 펌웨어 · 마지막 수신 · 점검 회차. 10초 넘게 출력이 없으면 판정이 빨갛게 바뀝니다
- 포트는 Pico 로 보이는 것을 자동으로 고르고, USB 를 뺐다 꽂으면 저절로 다시 연결합니다. 버튼에 마우스를 올리면 설명이 뜹니다.
  단축키: `F5` 포트 새로고침 · `Ctrl+L` 지우기

> 다른 프로그램(Thonny · Mu · 웹 터미널)이 같은 포트를 열고 있으면 연결되지 않습니다. 하나만 여세요.

### 🧰 60분 수업 — 선생님이 **전날** 해 둘 것

시행착오의 대부분은 회로가 아니라 **준비물**에서 납니다. 아래를 미리 끝내 두면 학생은 회로에만 집중합니다.

- [ ] **Pico 마다** CircuitPython 10.x 펌웨어 + `lib/`(같은 10.x 번들의 `adafruit_dht.mpy` · `adafruit_motor/`) +
      `code.py`(= `code_hardware_selftest.py`) 를 넣어 둔다. 한 대에서 실행해 내장 LED 가 깜빡이는지 확인
- [ ] **USB 케이블이 데이터 케이블인지** — 충전 전용이면 `CIRCUITPY` 드라이브가 안 보입니다
- [ ] 학생 노트북 한 대에서 **`pico_monitor/run_monitor.bat`** 이 열리고 Pico 가 연결되는지 확인 (파이썬 3.9 이상)
- [ ] **브레드보드 레일이 가운데서 끊긴 제품인지** 확인 (빨강·파랑 선이 중간에 끊겨 있음).
      끊겼으면 4줄을 잇는 짧은 점퍼를 키트에 넣어 둔다 — 안 이으면 아래쪽 부품(DHT11·CdS·RGB)에 전원이 없습니다
- [ ] **외부 5V 연결 방법**을 정해 둔다. 브레드보드 전원 모듈을 쓰면 **왼쪽 5V, 오른쪽 OFF** 로 점퍼를 맞춰서 배부
      (오른쪽 레일은 Pico 3V3 자리 — 5V 가 들어가면 Pico 가 망가집니다)
- [ ] 교실 조명에서 한 대로 조도 값을 재서 `LIGHT_REF` 를 고쳐 둔다 (기본 85)
- [ ] 학생에게는 **`../worksheets/수정 배선도.pdf`** 를 나눠 준다 (SG90 은 보드 밖에서 점퍼 3개, RGB 모듈은 위에서부터 R·G·B·GND)
- [ ] DHT11 · RGB 모듈 **핀 순서가 수정 배선도(VCC·DATA·GND / R·G·B·GND)와 같은지** 키트 하나로 확인. 다르면 칠판에 적어 둔다
- [ ] 팀별 봉투: 점퍼(빨강·검정·주황·신호색) · 10kΩ · CdS · 커패시터 · 모듈 3종 · 서보

### ⏱️ 60분 진행 — 하나 꽂고 바로 확인

점검 코드가 **처음부터 돌고 있으므로**, 부품을 하나 꽂을 때마다 시리얼 모니터에서 그 줄이 `[실패]` → `[OK]` 로
바뀌는 것을 보며 진행합니다. 한꺼번에 다 꽂고 찾는 것보다 훨씬 빠릅니다.
(선을 꽂고 뺄 때는 **USB 를 뽑고**, 다 꽂은 뒤 다시 연결합니다. 잘못 꽂은 선이 3V3 와 GND 를 잇는 순간 Pico 가 꺼지거나 망가질 수 있습니다.
다시 연결하면 코드가 저절로 시작하고, 시리얼 모니터는 포트만 다시 열면 됩니다. **서보·외부 5V 는 어댑터도 뽑은 상태에서** 연결합니다)

| 시간 | 할 일 | 확인 |
|---|---|---|
| 0~5분 | 수정 배선도 나눠 주기 · 선생님이 **최종 배선도의 「꼭 확인할 것」 · 색 규칙**을 화면에 띄워 같이 읽기 (수정 배선도에는 설명 패널이 없음) | 레일 끊김 여부 각 팀이 확인 |
| 5~12분 | Pico 꽂기(1~20행) · USB 연결 · 시리얼 모니터 열기 · 3V3·GND 레일 · 공통 GND | **내장 LED 깜빡임** + 출력이 보임 |
| 12~18분 | RGB 모듈 (위에서부터 R·G·B·GND) | 서보 없이도 도착 시점마다 색이 바뀜 |
| 18~26분 | DHT11 | 온도·습도 `[OK]` |
| 26~34분 | 10kΩ + CdS | 조도 `[OK]`, 손으로 가리면 값이 내려감 |
| 34~38분 | 🙋 **손 들기 — 선생님 확인**: 커패시터 극성 · 서보 빨강이 왼쪽 레일(VBUS 아님) · 외부 5V 극성 | — |
| 38~46분 | 서보 + 외부 5V | 90→180→90→0→90, 리셋 없음 |
| 46~56분 | 고치기 · 다 된 팀은 다른 팀 도와주기 | 모든 줄 `[OK]` |
| 56~60분 | `code.py` → `code.py.bak` 이름 바꾸기, 정리 | 🚨 안 하면 다음 시간에 `main.py` 가 안 돕니다 |

> 서보를 아직 안 꽂았어도 점검 코드는 그대로 돕니다 — PWM 신호만 나가고, RGB 색은 도착 시점마다 바뀝니다.

## 추가 회로 단독 점검 — 초음파 · 릴레이 DC 모터 · PWM LED

`../worksheets/추가 배선도.pdf` 대로 조립한 회로를 **Pico 혼자서**, 또는 **PC 화면에서 버튼으로** 점검합니다.

| 파일 | 어디에 | 역할 |
|---|---|---|
| `code_extra_circuits.py` | `CIRCUITPY/code.py` 로 저장 | Pico 점검 코드 |
| `adafruit_hcsr04.mpy` | `CIRCUITPY/lib/` | 초음파 라이브러리 — **펌웨어와 같은 10.x 번들**에서. 없으면 `[준비] 라이브러리가 없습니다` 가 뜹니다 |
| `pico_monitor/pico_extra_ui.py` · `run_extra_ui.bat` | 학생 노트북 (`pico_monitor` 폴더째) | 버튼으로 조작하는 점검 화면. 같은 폴더의 `pico_monitor.py` · pyserial 휠을 함께 씁니다 — **설치 없음** |

핀: TRIG **GP10** · ECHO **GP11**(1kΩ/2kΩ 분압 거쳐서) · 모터 **GP13** · LED **GP22**

> ⚠ **GP13 LOW = 모터 켜짐.** 포토커플러 모듈 입력이 3.3V 로는 부족해서 「IN1 = 5V, 입력 G = GP13」 으로 Pico 가 끌어내립니다.
> 모듈의 **입력 G ↔ 출력 G 점퍼는 반드시 뺍니다** — 꽂혀 있으면 GP13 이 GND 에 붙어 모터가 꺼지지 않습니다.
> 코드는 HIGH(꺼짐)로 시작하고, 멈추거나 Ctrl+C 를 누르면 모터 · LED 를 끄고 끝납니다.

**두 가지 상태**
- **자동 시험** (켜자마자) — 0.1초마다 거리 측정(최근 5개 중앙값) · LED 밝기 0→100→0 · 모터 2초 켜고 2초 끄기.
  PC 없이 시리얼 모니터만 봐도 `[거리] 23.4 cm · 모터 켜짐 · LED 50%` 줄이 1초마다 나옵니다
- **수동 조작** — UI 의 `수동 조작` · `켜기/끄기` · 밝기 슬라이더를 누르면 바뀝니다. `자동 시험` 버튼으로 돌아갑니다.
  🛡 수동 조작에서 **5초 동안 PC 신호가 없으면 모터를 끕니다** (창을 닫거나 USB 가 빠졌을 때). UI 는 1초마다 `PING` 을 보냅니다

**UI 화면** — 위에 포트 · 연결, 그 아래 지금 상태(자동/수동), 카드 3장(거리: 큰 숫자 · 0~100cm 막대 · 추세선 /
모터: 켜기 · 끄기 / LED: 밝기 미리보기 · 슬라이더 · 0·25·50·100%), 맨 아래 Pico 메시지.
초음파가 3번 연속 실패하면 거리가 `---` 로 바뀌고 확인할 배선이 빨갛게 나옵니다. 창을 닫으면 `MOTOR OFF` 를 보내고 닫힙니다.

|---|---|
| 거리 `---` | TRIG/ECHO 바뀜 · 분압 저항 위치(1kΩ 이 ECHO 쪽, 2kΩ 이 GND 쪽) · VCC 가 **5V** 인지 · 공통 GND |
| 모터가 계속 돌거나 안 멈춤 | 포토커플러 모듈 **입력 G ↔ 출력 G 점퍼**가 꽂혀 있음 |
| 릴레이 LED 는 켜지는데 모터가 안 돔 | 모터가 **NO** 가 아니라 NC 에 · COM 에 5V 가 없음 |
| 켜기를 눌렀는데 릴레이가 반대로 동작 | 릴레이 모듈이 LOW 트리거 제품 — 모듈의 점퍼(H/L)를 H 로, 없으면 선생님께 |
| LED 가 안 밝아짐 | LED 극성(긴 다리가 GP22 쪽 저항으로) · 220Ω |

> 점검이 끝나면 `code.py` 를 지우거나 `code.py.bak` 으로 — 안 그러면 `main.py` 가 실행되지 않습니다.

## 오늘의 교육 포인트 — **가져올 것과 가져오면 안 되는 것**

학생이 가상 Pico 파일을 올리면, AI 는 **그 파일의 코드 구조까지 Pico 로 옮기려** 합니다.
**그것이 오늘의 가장 큰 함정입니다.** 두 파일은 **같은 언어가 아닙니다.**

| | 가상 Pico (`mock_pi_08.py`) | 진짜 Pico (`main.py`) |
|---|---|---|
| 언어 | **CPython** (PC 용 파이썬) | **CircuitPython** |
| WebSocket | `socket` 으로 **직접 구현** (핸드셰이크·프레임까지) | **`adafruit_httpserver`** 가 해 줌 |
| 동시 처리 | `threading` | **`asyncio`** (`create_task` · `gather`) |
| 센서 값 | `random` · `math.sin()` 으로 **지어냄** | **`analogio` · `digitalio`** 로 실제 핀에서 |
| 기다리기 | `time.sleep(1)` | **`await async_sleep(1)`** |
| 콘솔 명령 | `x` · `add` · `fail` | **없음** — 실물에는 그런 것이 없습니다 |

> ✅ **가져올 것은 하나뿐입니다 — 「무엇을 보내는가」.**
> `build_payload()` 의 **JSON 키 목록**과 `apply_command()` 가 **받는 키**.
> 통신 구조는 학생의 `main.py` 에 있는 것을 **그대로 둡니다.**

이 내용을 `프로젝트-규칙.md` **§11** 에 넣어 두었습니다. 규칙 문서를 같이 올리면
AI 가 먼저 읽고 알아서 피합니다.

## 핵심 — 3주차 `main.py` 는 키를 **두 개 빠뜨리고** 있습니다

<table>

| JSON 키 | 가상 Pico | 3주차 `main.py` | 진짜 Pico 에서 만드는 법 |
|---|:---:|:---:|---|
| `temperature` | ✅ | ✅ | `adafruit_dht.DHT11` (**2초 이상 간격**) |
| `humidity` | ✅ | ✅ | 〃 |
| `light_percent` | ✅ | ✅ | `analogio.AnalogIn(board.GP26)` |
| **`cpu_temp`** | ✅ | ❌ **없음** | **`microcontroller.cpu.temperature`** — 부품 없이 읽힙니다 |
| **`discomfort`** | ✅ | ❌ **없음** | **`0.81*t + 0.01*h*(0.99*t - 14.3) + 46.3`** |
| 팀 센서 (`soil` 등) | 콘솔 `add` | ❌ 없음 | 실제 핀에서 읽기 |

</table>

**이 두 키가 빠진 채로 전시에 나가면** 화면의 「칩 온도」와 「불쾌지수」 카드에
**「데이터 없음」이 그대로 남습니다.** 프롬프트 0 이 그것을 찾아내게 하는 질문입니다.

> 💡 **`cpu_temp` 가 가장 먼저 성공합니다.** 칩 안에 들어 있는 온도계라 **배선을 하나도
> 안 해도** 값이 나옵니다. 실물 Pico 로 넘어간 첫 성공 경험으로 좋습니다.
