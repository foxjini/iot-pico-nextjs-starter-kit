## 연동 확인 — 인터페이스 · 전압 · 전류

| 부품 | 판단 | 연결 |
|---|---|---|
| 조이스틱 | 가변저항으로 전압을 나누는 장치라 **출력 = 넣어 준 전압의 0~100%** 입니다. 「+5V」 핀에 5V 를 넣으면 출력이 5V 까지 올라가 Pico ADC 한계(3.3V)를 넘습니다. **→ 「+5V」 핀에 3V3 를 넣습니다.** 출력은 0~3.3V, 값은 0~65535 | VRx → GP26(ADC0), VRy → GP27(ADC1), SW → GP22(내부 풀업) |
| 스텝모터 | ULN2003 입력은 3.3V 로도 켜집니다(달링턴 · 입력 저항 내장). 모터는 **5V · 약 200~240mA**(2상 여자, 코일 약 50Ω) | IN1~IN4 → GP10~GP13, + → **외부 5V**, − → GND |
| LCD | LCD 는 5V 라야 글자가 선명합니다. 변환 모듈의 풀업 저항이 SDA · SCL 을 5V 까지 끌어올리므로 **레벨 변환**을 거칩니다 | GP4 → LV1 / HV1 → SDA, GP5 → LV2 / HV2 → SCL, LV → 3V3, HV → 5V, GND(HV 쪽) → GND |
| RC522 | 3.3V 칩, SPI 3.3V 신호 그대로 | SCK GP18 · MOSI GP19 · MISO GP16 · SDA(CS) GP17 · RST GP20 · 3.3V → 3V3 · IRQ 비움 |

### 레벨 변환을 거쳐도 I2C 속도가 괜찮은가? — **예 (100kHz)**
- I2C 는 100kHz(표준 모드)로 씁니다. LCD 의 PCF8574 자체가 **최대 100kHz** 라 더 빠르게 할 이유가 없습니다.
- BSS138 모듈은 신호가 올라갈 때 풀업 저항으로 올립니다. 양쪽 10kΩ 과 LCD 모듈의 4.7kΩ 이 함께 걸리고 선 용량이 수십 pF 이면 **올라가는 시간 ≈ 0.2~0.5μs** 입니다. 표준 모드 허용치는 1μs 라 여유가 있습니다. 400kHz(허용 0.3μs)는 경계선이라 쓰지 않습니다.
- 실제 시간: 글자 1개 = I2C 6바이트 ≈ 0.6ms, 한 줄 16자 ≈ 10ms, 두 줄 ≈ 20ms. 카드를 댈 때만 다시 쓰므로 조이스틱 · 모터 반응에는 영향이 없습니다.

### 스텝모터에 별도 전원이 필요한가? — **예 (외부 5V 어댑터)**
- Pico 의 3V3 핀으로는 5V 모터를 돌릴 수 없습니다.
- VBUS(USB 5V)는 PC 포트 기준 500mA 입니다. Pico · LCD 백라이트 · RC522 와 모터(200~240mA, 돌기 시작할 때 더 큼)가 이것을 나눠 쓰면 순간 전압이 떨어져 Pico 리셋이나 USB 끊김이 생길 수 있습니다.
- 그래서 **5V 2A 어댑터 → 왼쪽 레일(5V)** 로 모터 · LCD · 레벨 변환 HV 에 전원을 넣고, 470μF 를 레일에 꽂습니다.
- 오른쪽 레일은 **Pico 3V3(3.3V)** 로 조이스틱 · RC522 · 레벨 변환 LV 에만 씁니다. 합계 약 30mA 라 여유가 충분합니다.
- **GND 는 Pico · 어댑터 · 모든 모듈 공통.** 전원 순서: 켤 때 USB 먼저 → 어댑터, 끌 때 · 선 바꿀 때 어댑터 먼저.

> **레벨 변환을 넣는 까닭.** Pico W(RP2040)의 핀은 5V 를 견디지 못합니다.
> Pico 2 W(RP2350)는 핀이 5V 를 견딘다고 알려져 있지만, 이번 자료를 만들 때 공식 데이터시트에 접속할 수 없어 확인하지 못했습니다.
> 그래서 두 보드 모두에 안전한 레벨 변환을 기본으로 했습니다. **선생님이 RP2350 데이터시트로 5V 허용을 직접 확인한 경우에만**
> Pico 2 W 에서 레벨 변환을 빼고 SDA · SCL 을 GP4 · GP5 에 바로 이을 수 있습니다(Pico W 에서는 절대 안 됩니다).

**시험 순서.** 부품을 하나 꽂을 때마다 그 테스트 파일을 `code.py` 로 이름 바꿔 저장하고 확인합니다.
순서는 test1 → test2 → test3 → test4 이고, 마지막에 원래 `code.py` 를 넣습니다.
시리얼 모니터(115200)나 `pico_monitor` 앱으로 메시지를 봅니다.

**통합 `code.py` 동작**
- 조이스틱 X: 가운데 ±7% 는 정지. 기울기에 따라 반 스텝 간격 8ms ~ 1.3ms(약 11rpm). 놓으면 코일을 꺼서 발열을 막습니다.
- 버튼: 지금 위치를 0° 로 잡습니다.
- RFID: 1줄 「Card UID:」, 2줄 「DE AD BE EF」 형태. 같은 카드를 계속 대고 있으면 한 번만 표시하고, 떼었다 다시 대면 다시 표시합니다.
- 시작할 때 장치마다 점검합니다. LCD 나 RC522 가 없으면 원인을 안내하고 나머지는 그대로 동작합니다.
- PC 앱용 줄 `DATA {...}` 를 0.2초마다 보냅니다(`jx` · `jy` %, `sw`, `moving` -1/0/1, `mode` joy/pc/idle, `pos` · `angle`, `uid`, `lcd` 두 줄, `lcd_addr`, `rc_ver`).

**PC 명령** (시리얼에 한 줄씩 — 앱 버튼이 보내는 것과 같음)

| 명령 | 하는 일 |
|---|---|
| `STATUS` | 지금 상태를 한 번 더 보냄 |
| `ZERO` | 지금 위치를 0° 로 |
| `MOVE +90` · `MOVE -90` · `MOVE 360` | 그 각도만큼 돌고 멈춤 |
| `STOP` | 바로 멈춤 |
| `LCD 글자1\|글자2` | LCD 표시 시험 (영문 · 숫자, 줄마다 16자) |

조이스틱을 기울이면 진행 중인 PC 명령은 취소되고 조이스틱이 우선합니다.

1 · 2차 때의 앱과 같은 방식입니다. 설치할 것이 없고(Python 기본 tkinter), `run_assess_ui.bat` 을 두 번 누르면 열립니다.

- LCD · RFID: LCD 두 줄을 실물처럼 보여 줌, 마지막 카드 번호와 시각, 글자 넣기 → LCD

## 증상별 확인

| 증상 | 확인 |
|---|---|
| 모터가 떨기만 하고 안 돎 | IN1~IN4 순서(GP10→IN1 …) · 외부 5V · On/Off 점퍼 · 흰 커넥터 끝까지 |
| 모터가 전혀 안 움직이고 ULN2003 LED 도 꺼짐 | 외부 5V 와 Pico GND 공통인지 · − · + 방향 |
| 조이스틱 가운데 값이 0 또는 65535 근처 | 「+5V」 핀이 3V3 레일에 있는지 · VRx/VRy 핀 |
| 오른쪽으로 밀었는데 반대로 돎 | 조이스틱을 돌려 끼운 것 — 정상. 코드의 `direction` 부호를 바꿔도 됨 |
| LCD 백라이트만 켜지고 네모 · 빈칸 | 뒤의 파란 가변저항(대비)을 드라이버로 돌리기 |
| 「LCD 를 못 찾음」 | SDA·SCL 이 바뀌지 않았는지 · 레벨 변환 LV=3V3 · HV=5V · LCD VCC=5V · GND 공통 |
| 「RC522 응답 없음」 · 버전 0x00/0xFF | 3.3V · GND · SCK/MOSI/MISO/SDA 핀 · RST=GP20 |
| 카드를 대도 번호가 없음 | 리더기 가운데 원 무늬에 1~3cm · 금속 책상 위 피하기 |
| 버전이 0x91 · 0x92 가 아님(예: 0x12 · 0xB2) | 호환 칩 — 대부분 그대로 동작 |

## 검증 (2026-11-23, PC 시뮬레이션)

가짜 `board` · `busio` · `digitalio` · `analogio` 를 만들고 CPython 에서 시험했습니다.
가짜 장치는 두 가지입니다. 가짜 PCF8574 · HD44780 은 받은 바이트로 화면 글자를 복원합니다.
가짜 MFRC522 는 레지스터 · FIFO · ISO 14443 의 IDLE/READY 상태를 흉내 냅니다.

- **통합 `code.py`: 31개 통과.** 확인한 것:
  - LCD 주소 자동 인식(0x27 · 0x3F), RC522 버전
  - 조이스틱 좌 · 우 · 가운데에 따른 방향 · 속도 · 정지, 놓으면 코일 끄기, 버튼으로 0°
  - 카드 → LCD, 같은 카드 한 번만 표시, 다른 카드 · 다시 대기, 모터가 도는 중에도 카드 읽기
  - Ctrl+C 때 정리, 장치가 없을 때 안내
  - `DATA` 줄, PC 명령 `ZERO` · `MOVE ±90` · `STOP` · `LCD` · 잘못된 명령, 조이스틱이 PC 명령보다 우선, 한글 입력이 들어와도 멈추지 않음
- **테스트 4개: 9개 통과.**

실물 하드웨어로는 시험하지 못했습니다. 특히 다음은 실물로 확인해 주세요:
