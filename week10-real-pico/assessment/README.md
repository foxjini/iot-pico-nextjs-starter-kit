## 연동 확인 — 인터페이스 · 전압 · 전류

| 부품 | 판단 | 연결 |
|---|---|---|
| 조이스틱 | 가변저항으로 전압을 나누는 장치라 **출력 = 넣어 준 전압의 0~100%** 입니다. 「+5V」 핀에 5V 를 넣으면 출력이 5V 까지 올라가 Pico ADC 한계(3.3V)를 넘습니다. **→ 「+5V」 핀에 3V3 를 넣습니다.** 출력은 0~3.3V, 값은 0~65535 | VRx → GP26(ADC0), VRy → GP27(ADC1), SW → GP22(내부 풀업) |
| 스텝모터 | ULN2003 입력은 3.3V 로도 켜집니다(달링턴 · 입력 저항 내장). 모터는 **5V · 약 200~240mA**(2상 여자, 코일 약 50Ω) | IN1~IN4 → GP10~GP13, + → **외부 5V**, − → GND |
| LCD | LCD 는 5V 라야 글자가 선명합니다. 변환 모듈의 풀업 저항이 SDA · SCL 을 5V 까지 끌어올리므로 **레벨 변환**을 거칩니다 | GP16 → LV1 / HV1 → SDA, GP17 → LV2 / HV2 → SCL, LV → 3V3, HV → 5V, GND 두 개 → GND |
| RC522 | 3.3V 칩, SPI 3.3V 신호 그대로 | SCK GP18 · MOSI GP19 · MISO GP20 · SDA(CS) GP21 · **RST · 3.3V → 3.3V 레일**(시작할 때 소프트 리셋) · IRQ 비움 |

### 레벨 변환기 꽂기 — 브레드보드에 **180° 돌려서** (HV 왼쪽)
- 보드 레일이 **왼쪽 = 외부 5V**, **오른쪽 = 3.3V** 입니다. 그래서 모듈을 **HV 가 왼쪽**이 되게 돌려 꽂습니다. 글씨가 거꾸로 보이는 것이 맞습니다.
  - 이렇게 하면 HV 는 5V 레일과 LCD 쪽, LV 는 3.3V 레일 쪽에 옵니다. 모든 점퍼가 짧고 서로 겹치지 않습니다.
  - 사진 방향(LV 왼쪽) 그대로 꽂으면 전원선과 LCD 선이 모두 보드를 가로질러야 합니다.
- **자리: Pico 아래 26~31행, 가운데 홈을 걸쳐** 꽂습니다(DIP 칩처럼). 행마다 왼쪽(A~E) · 오른쪽(F~J)이 따로 이어지므로, 핀 12개가 모두 따로 연결됩니다.
  - 돌린 순서라 위에서부터 26행 4채널 · 27행 3채널 · 28행 GND · 29행 HV/LV · 30행 2채널 · 31행 1채널입니다.
  - 배선도는 핀 두 줄 사이를 **5칸(D · G 열)** 으로 그렸습니다. 사진으로 짐작한 값이라 실물로 세어 보세요. 4칸이면 E · G 열에 꽂습니다. 같은 행이면 연결은 똑같습니다.
- 점퍼

| 점퍼 | 이어지는 것 |
|---|---|
| A29 → 왼쪽 + 레일(5V) | HV |
| A28 → 왼쪽 − 레일 | GND (HV 쪽) |
| J29 → 오른쪽 + 레일(3.3V) | LV |
| J28 → 오른쪽 − 레일 | GND (LV 쪽) |
| **I19 → H30** | GP17 → LV2 (SCL) |
| **J20 → I31** | GP16 → LV1 (SDA) |
| LCD SDA → A31, LCD SCL → A30 | HV1 · HV2 |

- I2C 를 GP16 · GP17 로 옮긴 까닭: 모듈 바로 위 행이라 점퍼가 짧고, RC522 선과 겹치지 않습니다.
  - 그래서 RC522 는 MISO GP20 · SDA(CS) GP21 로 옮겼습니다. SPI0 의 RX 핀이 GP16 · GP20 이라 둘 다 됩니다.
  - **RST 는 3.3V 레일**에 바로 꽂습니다. RST 를 HIGH 로 두면 칩이 늘 켜져 있고, 코드가 시작할 때 소프트 리셋을 합니다. 이렇게 하면 조이스틱 위를 지나는 긴 선이 없어집니다.

### LCD · RC522 놓는 방향 — 10cm 점퍼선에 맞춰 **둘 다 180° 돌려서**
**LCD 는 화면이 보이게 두되 180° 돌려 놓습니다.** I2C 핀이 오른쪽(Pico 쪽)에 오고, 위에서부터 **SCL · SDA · VCC · GND** 순서가 됩니다.
- 똑바로 놓으면 핀이 왼쪽 끝이라 10cm 점퍼가 Pico 까지 닿지 않습니다.
- 돌려 놓으면 글자가 거꾸로 보이므로, `code.py` 의 **`LCD_FLIP = True`**(기본)로 글자를 뒤집어 그립니다. 돌려 놓은 LCD 를 보면 똑바로 읽힙니다.
  - HD44780 칩에는 화면을 뒤집는 기능이 없습니다. 그래서 글자마다 180° 돌린 모양을 사용자 글자(CGRAM 8칸)로 만들고, 줄 순서 · 글자 순서도 거꾸로 씁니다(`lcd_i2c.py` 의 `draw()`).
  - 0 · 8 · H · I · N · O · S · X · Z · 기호와 6↔9 는 돌려도 LCD 에 있는 글자라 칸을 쓰지 않습니다.
  - **한계**: 한 화면에 그 밖의 글자가 8종류를 넘으면, 넘친 글자는 비슷한 글자로 대신 나옵니다(예: A→V, E→3). 카드 번호 화면은 1줄(16진수)이 먼저 칸을 받아 늘 정확하고, 「.」 은 칸이 모자라면 「,」 처럼 보입니다. 첫 화면 · 알림 글자는 8종류 안에 들도록 대문자로 바꿨습니다(「TAP RFID CARD / X=MOTOR」).
  - LCD 를 똑바로 놓고 쓸 때는 `LCD_FLIP = False`, 또는 앱의 「글자 뒤집기」 버튼(`FLIP` 명령)으로 끕니다.
- 선: SCL → A30, SDA → A31 (레벨 변환 HV2 · HV1 행), VCC → 왼쪽 + 레일 32행, GND → 왼쪽 − 레일 33행. 네 선이 나란히 내려가 서로 겹치지 않습니다.

**RC522 도 180° 돌려 핀을 왼쪽(Pico 쪽)에 둡니다.** 위에서부터 **SDA · SCK · MOSI · MISO · IRQ · GND · RST · 3.3V** 순서입니다. 기판 글씨는 거꾸로 보이는 것이 맞습니다.
- SDA → J14(GP21), SCK → J17(GP18), MOSI → J16(GP19), MISO → J15(GP20), GND → 오른쪽 − 레일 22행, RST → 오른쪽 + 레일 23행, 3.3V → + 레일 24행, IRQ 비움.
- 핀 연결(GPIO)은 그대로이고 놓는 방향만 바뀌었습니다. 코드는 바꿀 것이 없습니다.

### 레벨 변환을 거쳐도 I2C 속도가 괜찮은가? — **예 (100kHz)**
- I2C 는 100kHz(표준 모드)로 씁니다. LCD 의 PCF8574 자체가 **최대 100kHz** 라 더 빠르게 할 이유가 없습니다.
- BSS138 모듈은 신호가 올라갈 때 풀업 저항으로 올립니다. 양쪽 10kΩ 과 LCD 모듈의 4.7kΩ 이 함께 걸리고 선 용량이 수십 pF 이면 **올라가는 시간 ≈ 0.2~0.5μs** 입니다. 표준 모드 허용치는 1μs 라 여유가 있습니다. 400kHz(허용 0.3μs)는 경계선이라 쓰지 않습니다.
- 실제 시간: 글자 1개 = I2C 6바이트 ≈ 0.6ms, 한 줄 16자 ≈ 10ms, 두 줄 ≈ 20ms. 카드를 댈 때만 다시 쓰므로 조이스틱 · 모터 반응에는 영향이 없습니다.

### 스텝모터에 별도 전원이 필요한가? — **예 (외부 5V 어댑터)**
- Pico 의 3V3 핀으로는 5V 모터를 돌릴 수 없습니다.
- VBUS(USB 5V)는 PC 포트 기준 500mA 입니다. Pico · LCD 백라이트 · RC522 와 모터(200~240mA, 돌기 시작할 때 더 큼)가 이것을 나눠 쓰면 순간 전압이 떨어져 Pico 리셋이나 USB 끊김이 생길 수 있습니다.
- 그래서 **5V 2A 어댑터 → 왼쪽 레일(5V)** 로 모터 · LCD · 레벨 변환 HV 에 전원을 넣고, 470μF 를 레일에 꽂습니다.
- 오른쪽 레일은 **Pico 3V3(3.3V)** 로 조이스틱 · RC522 · 레벨 변환 LV 에만 씁니다. 합계 약 30mA 라 여유가 충분합니다.
- **GND 는 Pico · 어댑터 · 모든 모듈 공통.** 전원 순서: 켤 때 USB 먼저 → 어댑터, 끌 때 · 선 바꿀 때 어댑터 먼저.

> **레벨 변환을 넣는 까닭.** Pico W(RP2040)의 핀은 5V 를 견디지 못합니다.
> Pico 2 W(RP2350)는 핀이 5V 를 견딘다고 알려져 있지만, 이번 자료를 만들 때 공식 데이터시트에 접속할 수 없어 확인하지 못했습니다.
> 그래서 두 보드 모두에 안전한 레벨 변환을 기본으로 했습니다. **선생님이 RP2350 데이터시트로 5V 허용을 직접 확인한 경우에만**
> Pico 2 W 에서 레벨 변환을 빼고 SDA · SCL 을 GP16 · GP17 에 바로 이을 수 있습니다(Pico W 에서는 절대 안 됩니다).

|---|---|
| `lcd_i2c.py` | LCD 드라이버 (PCF8574 + HD44780, 주소 자동 찾기) — **항상 함께 넣기** |
| `mfrc522_lite.py` | RC522 카드 번호 읽기 드라이버 — **항상 함께 넣기** |
| `test1_joystick.py` | 조이스틱만: X · Y %, 버튼 |

| `test3_lcd.py` | LCD 만: I2C 주소 찾기 → 「Hello Pico 2 W」 |

**시험 순서.** 부품을 하나 꽂을 때마다 그 테스트 파일을 `code.py` 로 이름 바꿔 저장하고 확인합니다.
순서는 test1 → test2 → test3 → test4 이고, 마지막에 원래 `code.py` 를 넣습니다.
시리얼 모니터(115200)나 `pico_monitor` 앱으로 메시지를 봅니다.

**통합 `code.py` 동작**
- 조이스틱 X: 가운데 ±7% 는 정지. 기울기에 따라 반 스텝 간격 8ms ~ 1.3ms(약 11rpm). 놓으면 코일을 꺼서 발열을 막습니다.
- RFID: LCD 1줄에 16진수 번호, 2줄에 ASCII 를 씁니다. 0x20~0x7E 밖의 값은 `.` 으로 바꿉니다.
  - 예) `6A 70 F4 BC` → 1줄 「6A 70 F4 BC」, 2줄 「ASCII: jp..」 (6A=`j`, 70=`p`, F4 · BC 는 찍을 수 없는 값)
  - 같은 카드를 계속 대고 있으면 한 번만 표시하고, 떼었다 다시 대면 다시 표시합니다.
- 조이스틱 Y: LCD 의 카드 표시를 **전광판처럼 돌립니다**. 끝으로 나간 글자는 반대쪽에서 다시 나오고, 두 줄이 함께 돕니다.
  - Y + (위) → 오른쪽으로 한 칸씩. 예) 「6A 70 F4 BC     」 → 「 6A 70 F4 BC    」 → … → 「C     6A 70 F4 B」
  - Y - (아래) → 왼쪽으로 한 칸씩
  - 기울이고 있는 동안 계속 돕니다. 조금 기울이면 0.4초, 끝까지 기울이면 0.12초 간격입니다. X(모터)와 함께 움직여도 됩니다.
  - 이 조이스틱 모듈은 Y 값이 반대로 나와서, 코드에서 부호를 바꿔 「위 = +」 로 맞췄습니다.
- 버튼(SW): **LCD 카드 표시를 원래대로** 되돌리고, 지금 모터 위치를 0° 로 잡습니다.
- 장치 다시 찾기: 시작할 때 LCD 나 RC522 가 없으면 원인을 안내하고, 나머지는 그대로 동작합니다.
  - 그 뒤 **3초마다 다시 찾습니다.** 선을 고쳐 꽂으면 Pico 를 다시 시작하지 않아도 저절로 연결되고(「[연결] … 다시 찾았습니다」), LCD 는 새로 초기화한 뒤 하던 화면을 다시 그립니다.
  - 도중에 빠져도 3초 안에 알아채고(「[LCD] 연결이 끊겼습니다」) 다시 찾기 시작합니다.
  - 그래도 안 되면 앱의 **「↻ Pico 재시작」** 버튼이나 `RESTART` 명령으로 code.py 를 처음부터 다시 실행합니다(Ctrl+D 와 같음).
- PC 앱용 줄 `DATA {...}` 를 0.2초마다 보냅니다(`jx` · `jy` %, `sw`, `moving` -1/0/1, `mode` joy/pc/idle, `pos` · `angle`, `uid`, `ascii`, `rot`(돌린 칸 수), `lcd` 두 줄, `lcd_addr`, `rc_ver`).

**PC 명령** (시리얼에 한 줄씩 — 앱 버튼이 보내는 것과 같음)

| 명령 | 하는 일 |
|---|---|
| `STATUS` | 지금 상태를 한 번 더 보냄 |
| `ZERO` | 지금 위치를 0° 로 |
| `MOVE +90` · `MOVE -90` · `MOVE 360` | 그 각도만큼 돌고 멈춤 |

| `LCD 글자1\|글자2` | LCD 표시 시험 (영문 · 숫자, 줄마다 16자) |
| `FLIP` · `FLIP ON` · `FLIP OFF` | LCD 글자 뒤집기 바꾸기 · 켜기 · 끄기 (앱의 「글자 뒤집기」 버튼) |
| `RESTART` | code.py 를 처음부터 다시 실행 — LCD · RC522 · 조이스틱 가운데를 새로 잡음 (앱의 「↻ Pico 재시작」) |

조이스틱을 기울이면 진행 중인 PC 명령은 취소되고 조이스틱이 우선합니다.

## PC 테스트 앱 — `pico_monitor/pico_assess_ui.py`

1 · 2차 때의 앱과 같은 방식입니다. 설치할 것이 없고(Python 기본 tkinter), `run_assess_ui.bat` 을 두 번 누르면 열립니다.
- 맨 위: 포트 · 연결, 한 줄 판정과 **「↻ Pico 재시작」** 버튼, 점검 칸 8개(연결 · 코드 · LCD · RC522 · 조이스틱 가운데 · 버튼 · 모터 · 카드)
- 조이스틱: 과녁 안에서 점이 기울기를 따라 움직임(위 = Y +, LCD 오른쪽으로 돌림), X · Y %, 버튼
- 스텝모터: 각도 바늘, `-90°` · `+90°` · `한 바퀴` · `멈춤` · `0° 맞추기` 버튼
- LCD · RFID: LCD 두 줄을 실물처럼 보여 줌(돌린 모습 그대로), 마지막 카드 번호 · ASCII · 돌린 칸 수 · 읽은 시각, 글자 넣기 → LCD
- 메시지 창: Pico 출력과 원인별 안내. 빠졌던 LCD · RC522 가 다시 연결되면 「✔ 다시 연결되었습니다」

## 증상별 확인

| 증상 | 확인 |
|---|---|
| 모터가 떨기만 하고 안 돎 | IN1~IN4 순서(GP10→IN1 …) · 외부 5V · On/Off 점퍼 · 흰 커넥터 끝까지 |
| 모터가 전혀 안 움직이고 ULN2003 LED 도 꺼짐 | 외부 5V 와 Pico GND 공통인지 · − · + 방향 |
| 조이스틱 가운데 값이 0 또는 65535 근처 | 「+5V」 핀이 3V3 레일에 있는지 · VRx/VRy 핀 |
| 오른쪽으로 밀었는데 반대로 돎 | 조이스틱을 돌려 끼운 것 — 정상. 코드의 `direction` 부호를 바꿔도 됨 |
| LCD 백라이트만 켜지고 네모 · 빈칸 | 뒤의 파란 가변저항(대비)을 드라이버로 돌리기 |
| 선을 고쳐 꽂았는데도 LCD · RC522 가 안 잡힘 | 3초 기다리기(저절로 다시 찾음) → 그래도 안 되면 앱의 「↻ Pico 재시작」 |
| 「LCD 를 못 찾음」 | SDA·SCL 이 바뀌지 않았는지 · 레벨 변환을 HV 가 왼쪽이 되게(글씨 거꾸로) 꽂았는지 · 점퍼 I19→H30 · J20→I31 · LCD VCC=5V · GND 공통 |
| 「RC522 응답 없음」 · 버전 0x00/0xFF | 3.3V · GND · SCK=GP18 · MOSI=GP19 · MISO=GP20 · SDA=GP21 · RST=3.3V 레일 |
| 카드를 대도 번호가 없음 | 리더기 가운데 원 무늬에 1~3cm · 금속 책상 위 피하기 · 13.56MHz 카드인지. 버전은 정상인데 계속 안 읽히면 **모듈 불량**일 수 있음(다른 RC522 로 바꿔 보기 — 실제로 모듈을 바꿔 해결한 사례 있음) |
| Y 를 위로 밀었는데 LCD 가 왼쪽으로 돎 | 조이스틱을 돌려 끼운 것 — code.py 의 `st.py = -percent(...)` 에서 `-` 를 지우기 |
| 버전이 0x91 · 0x92 가 아님(예: 0x12 · 0xB2) | 호환 칩 — 대부분 그대로 동작 |

## 검증 (2026-11-24, PC 시뮬레이션)

가짜 `board` · `busio` · `digitalio` · `analogio` 를 만들고 CPython 에서 시험했습니다.
가짜 장치는 두 가지입니다. 가짜 PCF8574 · HD44780 은 받은 바이트로 화면 글자를 복원합니다.
가짜 MFRC522 는 레지스터 · FIFO · ISO 14443 의 IDLE/READY 상태를 흉내 냅니다.

- **통합 `code.py`: 50개 통과.** 확인한 것:
  - LCD 주소 자동 인식(0x27 · 0x3F), RC522 버전
  - 조이스틱 좌 · 우 · 가운데에 따른 방향 · 속도 · 정지, 놓으면 코일 끄기, 버튼으로 0°
  - 카드 → LCD, 같은 카드 한 번만 표시, 다른 카드 · 다시 대기, 모터가 도는 중에도 카드 읽기
  - Ctrl+C 때 정리, 장치가 없을 때 안내
  - `DATA` 줄, PC 명령 `ZERO` · `MOVE ±90` · `STOP` · `LCD` · 잘못된 명령, 조이스틱이 PC 명령보다 우선, 한글 입력이 들어와도 멈추지 않음
  - Y 부호, `6A 70 F4 BC` → `jp..`, Y + 로 오른쪽 · Y - 로 왼쪽 돌리기(글자가 사라지지 않음), 버튼으로 원래대로, X · Y 함께
  - 글자 뒤집기: 가짜 LCD 가 DDRAM · CGRAM 을 그대로 흉내 내고, 화면 픽셀을 180° 돌려 글자를 읽어 냄(「돌려 놓은 LCD 를 보는 사람」) → 카드 화면 · 첫 화면 · 알림 · LCD 명령이 똑바로 읽힘, `FLIP OFF` 면 똑바로 놓은 LCD 에서 읽힘
  - 처음에 없던 LCD · RC522 를 나중에 꽂으면 3초 안에 연결, 도중에 빠지면 알아채고 다시 꽂으면 LCD 를 새로 초기화해 화면 복원, `RESTART` 로 처음부터
- **점검 앱**: 진짜 code.py 와 가상 시리얼로 이어 확인 — 돌린 LCD 미리보기 · ASCII, 장치를 나중에 꽂았을 때 칸이 ✔ 로 바뀜, 「↻ Pico 재시작」
- **테스트 4개: 9개 통과.**
