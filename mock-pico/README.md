# 가상 Pico — 실물 Pico 2 W 없이 실습하기

실제 Raspberry Pi Pico 2 W 가 없어도 **2 · 3 · 8 · 9 · 11 · 12주차** 실습을
그대로 진행할 수 있게 해 주는 프로그램입니다. 윈도우 PC 의 파이썬으로 실행하면,
그 PC 가 Pico 인 척하면서 대시보드에 센서값을 보내고 제어 명령을 받습니다.

```
브라우저(대시보드)  ←  WebSocket / REST  →  mock_pi_XX.py  (Pico 역할)
```

- 설치할 것이 없습니다. **파이썬 표준 라이브러리만** 씁니다 (`pip install` 불필요).
- 파일 한 개가 곧 프로그램입니다. 폴더 구조나 다른 파일에 의존하지 않습니다.
- 포트 번호, 주소, JSON 키 이름, 시리얼에 찍히는 문구를 **진짜 Pico 와 같게** 맞췄습니다.
  그래서 교재와 워크시트의 "시리얼 모니터에서 `[WS] 송신 메시지` 확인" 같은 지시를
  글자 그대로 따라갈 수 있습니다.

## 준비

| 항목 | 내용 |
| --- | --- |
| 파이썬 | 3.8 이상. 명령 프롬프트에서 `py --version` 으로 확인 |
| 설치 | 없음 |
| 부품 | 없음. USB 케이블도, CircuitPython 도 필요 없음 |

`py` 가 없다고 나오면 `python mock_pi_03.py` 또는 `python3 mock_pi_03.py` 로 실행하세요.

## 주차별 파일

| 파일 | 주차 | 통신 방식 | 보내는 센서 키 |
| --- | --- | --- | --- |
| `mock_pi_02.py` | 2주차 REST API + MySQL | HTTP (POST/GET) | temperature, humidity, light_percent |
| `mock_pi_03.py` | 3주차 WebSocket 실시간 대시보드 | WebSocket | temperature, humidity, light_percent |
| `mock_pi_08.py` | 8주차 Bootstrap 부품 10개 | WebSocket | (3주차와 같음) |
| `mock_pi_09.py` | 9주차 배열과 JSON 키 | WebSocket | + cpu_temp, discomfort |
| `mock_pi_11.py` | 11주차 바이브 코딩 | WebSocket | + 팀이 정한 키를 콘솔에서 추가 |
| `mock_pi_12.py` | 12주차 디자인 스타일과 레이아웃 | WebSocket | + soil (센서 6개로 미리 채움) |

받는 키는 모든 주차가 같습니다 — `led_r`, `led_g`, `led_b`, `servo_angle`.

## 켜는 방법

### 3 · 8 · 9 · 11 · 12주차 (WebSocket)

```
py mock_pi_03.py
```

실행하면 이런 줄이 뜹니다.

```
연결 완료! 내 IP 주소: 192.168.137.1
WebSocket 서버 시작: ws://192.168.137.1:5000/connect-websocket
```

대시보드의 IP 입력칸에 **여기 뜬 IP** 를 넣고 [연결] 을 누르세요.
같은 PC 의 브라우저에서 볼 거라면 `127.0.0.1` 을 넣어도 됩니다.

### 2주차 (REST API)

Next.js 를 먼저 `npm run dev:lan` 으로 켜 둔 다음:

```
py mock_pi_02.py                              (기본값 http://127.0.0.1:3000)
py mock_pi_02.py http://192.168.137.1:3000    (주소를 직접 줄 때)
```

3초마다 `/api/sensor` 로 POST 하고, 2초마다 `/api/actuator` 를 GET 합니다.
교재 `main.py` 의 주기와 같습니다.

## 콘솔 명령

프로그램이 돌아가는 창에 글자를 치고 Enter 를 누르면 상황을 바꿀 수 있습니다.
그냥 Enter 를 치면 명령 목록이 다시 나옵니다.

| 명령 | 하는 일 | 있는 주차 |
| --- | --- | --- |
| `d` | 조도를 18% 로 낮춤 (어둡게) | 전부 |
| `b` | 조도를 보통으로 | 전부 |
| `h` | 온도 31.5도 / 습도 85% (경고 조건) | 전부 |
| `n` | 전부 보통으로 되돌림 | 전부 |
| `s` | 지금 상태 보기 | 전부 |
| `q` | 종료 | 전부 |
| `f` | DHT11 고장 — 온도·습도·불쾌지수가 `null` | 2, 9, 11 |
| `l` | 조도 센서 고장 — `light_percent` 만 `null` | 9, 11 |
| `x` | 연결 끊기 (8주차) / USB 5초 뽑았다 꽂기 (11주차) | 8, 11 |
| `add <키> <최소> <최대>` | 팀 센서 키를 새로 만들어 보내기 시작 | 11, 12 |
| `del <키>` | 그 키를 빼기 | 11, 12 |
| `fail <키>` | 그 센서만 고장 내기 (`null`) | 11 |

## 수업에서 쓰는 곳

| 주차 | 장면 | 쓰는 명령 |
| --- | --- | --- |
| 2주차 | MySQL 에 값이 쌓이는지 확인 | `d` 로 값을 바꿔 보고 `SELECT` |
| 2주차 | 센서가 고장 나도 서버 전송이 멈추지 않는지 | `f` |
| 8주차 | 3단계 Badge — 연결 상태 표시 | `x` |
| 8주차 | 4단계 ProgressBar — 막대가 짧아지는지 | `d` |
| 8주차 | 6단계 Alert — 경고가 뜨는지 | `h` |
| 9주차 | 6단계 버그 실험 (`?? 0` 과 `!= null` 비교) | `l` |
| 9주차 | 센서 하나가 죽어도 나머지 카드는 살아 있는지 | `f` |
| 11주차 | 프롬프트 4 자동 재연결 (전시회 필수) | `x` |
| 11주차 | 아직 부품이 없는 팀 센서의 키·화면 먼저 맞추기 | `add` |
| 12주차 | 대형 강조 / 균등 배치 / 사이드바 레이아웃 비교 | 그냥 켜 두기 (센서 6개) |

**9주차 6단계 실험이 이 프로그램의 가장 큰 쓸모입니다.** 실물 조도 센서를
뽑는 것으로는 `null` 을 만들기 어렵지만, `l` 을 누르면 정확히 그 상황이 됩니다.

## 자주 나는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| `포트 5000 을 열 수 없습니다` | 다른 가상 Pico 창이 이미 켜져 있습니다. 그 창에서 `q` 를 누르거나 창을 닫고 다시 실행 |
| 방화벽 창이 뜸 | `[개인 네트워크]` 와 `[공용 네트워크]` 를 모두 체크하고 `[액세스 허용]` |
| 대시보드가 연결되지 않음 | 대시보드에 넣은 IP 가 실행 화면에 뜬 IP 와 같은지 확인. 같은 PC 면 `127.0.0.1` |
| 창의 한글이 깨짐 | 명령 프롬프트에서 `chcp 65001` 을 한 번 실행한 뒤 다시 켜기 |
| `센서 전송 실패:` 가 계속 나옴 (2주차) | Next.js 가 켜져 있는지, 주소·포트가 맞는지 확인 |
| `명령 수신 실패:` 가 계속 나옴 (2주차) | `/api/actuator` 가 `led_r`/`led_g`/`led_b`/`servo_angle` 네 개를 모두 돌려주는지 확인 |
| 여러 사람이 같은 PC 에 붙음 | 진짜 Pico 처럼 **한 번에 한 명만** 연결됩니다. 나중에 붙은 쪽이 이깁니다 |

## 진짜 Pico 와 다른 점

이 프로그램이 대신할 수 있는 것과 못 하는 것을 분명히 알고 쓰세요.

**대신할 수 있는 것**

- WebSocket / REST 통신, JSON 키 맞추기, 화면 코드 작성과 디버깅
- 센서값이 `null` 일 때의 화면 동작 (9주차 6단계)
- 연결이 끊어졌다 붙는 상황 (8주차 Badge, 11주차 자동 재연결)
- 팀 센서를 아직 못 구했을 때, 키 이름과 카드 배치를 먼저 맞추기

**대신할 수 없는 것**

- 브레드보드 배선, 전압 확인, 저항 계산 → **1주차는 실물로** 해야 합니다
- 서보가 실제로 돌아가는 소리와 각도, RGB LED 의 실제 색
- SG90 전류 때문에 생기는 전원 문제 (외부 5V 레일, 커패시터, 공통 GND)
- 전시회 작품 → **실물 Pico 가 필요합니다**

센서값은 사인·코사인으로 만든 가짜 값입니다. 진짜 방 온도가 아니므로,
"값이 왜 계속 오르내리나요?" 라는 질문에는 그렇게 만들어 둔 것이라고 답해 주세요.

## 먼저 있던 `mock-pico*.js` 와의 관계

`week8-bootstrap-steps/mock-pico.js`, `week9-array-steps/mock-pico9.js`,
`week10-transplant/mock-pico10.js` 는 교재를 만들 때 화면을 검증하려고 쓴 Node.js 판입니다.
`npm install ws` 가 필요하고, 상황을 바꾸려면 환경변수를 바꿔 프로그램을 다시 켜야 합니다.

**수업에서는 이 폴더의 파이썬 판을 쓰세요.** 설치가 필요 없고, 창에서 글자 한 개를 쳐서
상황을 바로 바꿀 수 있습니다. 두 판의 프로토콜은 같으므로 대시보드는 어느 쪽에 붙어도 됩니다.
(10주차 Node 판은 파이썬 판이 따로 없습니다 — 압축 운영에서 10주차는 다루지 않습니다.)

## 검증 내용

이 파일들은 다음을 실제로 실행해 확인했습니다.

- WebSocket 핸드셰이크(RFC 6455): `Sec-WebSocket-Accept` 계산, 마스킹된 클라이언트
  프레임 해석, `ping` → `pong`, `close` → `close` 응답
- **진짜 크로미움 브라우저**로 `mock_pi_03.py` 에 접속해 값 수신과 명령 송신 확인
- 주차별 JSON 키가 교재·워크시트와 일치하는지 대조
- 2주차: POST 성공/서버 꺼짐/HTTP 500/응답 키 누락 네 경우 모두 프로그램이 죽지 않음
- 콘솔 명령 `d` `h` `f` `l` `x` `add` `del` `fail` `q` 의 동작
